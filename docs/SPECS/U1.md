## 2. `/demo` — the no-LLM / no-auth guarantee, and how it is enforced

`/demo` renders the **full** D1 dashboard (stat cards, AI overview, trend,
cap-strip, allocation bars, holdings table, source-empty callouts) for a visitor
with no account. It **makes no LLM call and no authenticated backend call, ever**
— a public route that generated narratives would let anonymous strangers burn
OpenAI credit, and it must be instant.

Enforced **structurally**, not by convention:

- **The data is committed, not fetched.** `frontend/lib/demo/dashboard.json`
  holds the frozen `/portfolio/summary` response, the pre-walked holdings buckets,
  and A1's overview artifact. `components/shell/DemoDashboard.tsx` imports it and
  calls no `fetch` — no `/portfolio/*`, no `/portfolio/overview`, no `/analyze`.
- **The overview is served statically.** `AiOverview` gained an additive
  `initial?: OverviewComplete` prop; when present it renders that overview and
  **skips the streaming effect entirely** (`if (initial) return;`) and hides
  Regenerate. `/demo` passes the committed artifact, so the narrative panel makes
  no request either.
- **`AuthProvider` is not global.** It used to be mounted in the root layout,
  where its warm-up ping (`/auth/status`, an authenticated endpoint) fired on
  every page including `/demo`. It now wraps only the surfaces that read
  `useIndMoney` — the Lab (`app/lab/layout`) and the flag-on landing
  (`app/(marketing)/page`) — so `/demo` mounts nothing that pings the backend.

**Proof:** loaded with the backend down (headless Chrome, network log),
`/demo` renders completely and makes **0** requests to any `:8000`,
`/portfolio/*`, `/overview`, or `/analyze` endpoint — flag-off **and** flag-on.
See `docs/TESTING/U1.md`.

### The demo fixture (regeneration)

`backend/scripts/gen_demo_dashboard.py` runs the real `StubConnector` through the
real route serializers (`api.routes.portfolio._snapshot_json` / `_holding_json`)
and reshapes A1's `backend/tests/fixtures/demo/overview.json`, writing
`frontend/lib/demo/dashboard.json`. The clock is pinned so the file is
byte-reproducible. 100% synthetic (the invented stub portfolio); `last_captured_at`
is null so the trend shows its honest empty state. Regenerate:

```bash
cd backend && python -m scripts.gen_demo_dashboard
```

The banner (`components/shell/DemoBanner.tsx`) is `position: sticky` — the
sample-data disclaimer stays on screen at **every** scroll position, because a
screenshot of a fake net worth with no context is genuinely misleading.

## 3. The chrome takeover (retiring D1's `TerminalChrome`)

D1 left `components/TerminalChrome.tsx` — a client component that returned the
terminal `<TopBar/>` everywhere except `/portfolio/*` — as the "dumbest
conditional that works", explicitly for U1 to delete. U1 deletes it and replaces
the app-wide conditional with **one clean per-surface mechanism**:

- **Terminal chrome** (dark Bloomberg `TopBar`) lives in `app/lab/layout.tsx` —
  the Lab is the surface whose aesthetic is deliberate. Visually unchanged.
- **shadcn chrome** (light `SiteHeader`) lives on the marketing group and `/demo`.
- **`/portfolio`** carries its own `PortfolioTopBar` (D1). Unchanged — the global
  terminal bar never rendered there anyway, so it is pixel-identical.
- The root layout injects **no** chrome; each surface declares its own.

`SiteHeader`'s identity slot (`SiteAuthSlot`) is flag-gated exactly like F2's
`UserMenu`: a `next/dynamic` import of a `components/clerk/` module, so flag-off
ships no Clerk. The landing's signed-in routing (`ClerkLanding`) is likewise a
`components/clerk/` module — `@clerk/nextjs` stays imported only from
`components/clerk/` and `middleware.ts` (the F2 containment invariant, still
enforced by the vitest source scan).

## 4. Landing routing

`app/(marketing)/page.tsx` returns the marketing hero flag-off (no Clerk, no
backend ping). Flag-on it wraps `AuthProvider` + `ClerkLanding`, which routes on
two **independent** facts — Clerk `isSignedIn` and the per-user IND Money link
(`useIndMoney`, F3):

| `isSignedIn` | `authed` | renders |
| --- | --- | --- |
| false / not loaded | — | the hero (children) |
| true | true | redirect → `/portfolio` |
| true | false | the Connect gate |
| true | null | a neutral "checking…" while the link resolves (no gate flash) |

Verified live against a real Clerk session (both link states) and pinned by
`frontend/tests/clerk-landing.test.tsx`.

## 5. `/privacy` + `/terms` — handoff to L1

Minimal reachable placeholders (`components/shell/LegalPage.tsx`) carrying a
`soon` badge and a "full policy at launch" note. They exist now so the
Privacy/Terms links D1, A1 and the demo already render on every page resolve to a
200 instead of a 404. **L1 writes the real content** (the DPDP delete-my-data
obligation, the full terms). The footer is D1's `PortfolioFooter`, reused across
the marketing group and `/demo`.

## 6. What U1 deliberately does not do

- **Does not flip `NEXT_PUBLIC_AUTH_ENABLED`.** That is L1's release. Every
  signed-in route behaves sanely both flag-off (no Clerk, the interim admin path)
  and flag-on.
- **Does not restyle `/portfolio` or `/lab`.** It adds routes and nav; those two
  surfaces are pixel-unchanged.
- **Does not write the privacy/terms policy text.** L1's.
- **Adds no backend runtime dependency.** The generator script is a build-time
  tool; the frontend adds no new package.
