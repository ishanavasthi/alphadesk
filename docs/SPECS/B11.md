# B11 — Lab confidence: make the number mean something (or stop drawing it as a bar)

**Status:** phases 0–2 done; phase 3 (gate) and phase 4 (presentation) built,
pending the model bake-off in §6.5. Not on `main`, **not deployed** — the live
desk still has the original bug. This is exploratory hardening of the Lab (a
labelled simulation on a paper watchlist), **not** investment advice — V2_PLAN
§8.3 bars instrument-level advice on real holdings and nothing here touches the
portfolio side.

> **§6 is the operator-facing report**: what the desk is doing, why, and the fix.
> Read that first; §0–5 are the working notes that produced it.

## 0. The problem

`AnalystRecommendation.confidence` (`agents/analyst.py`) is an LLM self-report.
The entire specification the model received was the token `confidence (0-1)` and
the schema description `"Confidence 0-1."` — nothing defined confidence *in what*,
over what horizon, against what evidence. That number then drives all three risk
verdicts (`agents/risk_manager.py`), sorts the per-sector cap, persists
denormalised into `watchlist`, and renders as a filled `ConfidenceBar` in
`components/RecommendationCard.tsx`.

## 1. Phase 0 — measurement (the gate)

`backend/evals/confidence_probe.py` scores the **real** Analyst path
(`_build_prompt` + the same `structured()` binding, minus the `except: return
None` that hides failures) over a fixed synthetic fixture set. It is deliberately
**not** a pytest test — `tests/conftest.py` scrubs provider keys (issue #31), so a
probe needing a real key cannot live there. Fixtures are synthetic (no user data);
run it with `python -m evals.confidence_probe`.

The design measures **signal vs noise**, not just a histogram:
- a **contrast set** of six setups an analyst should feel differently about;
- a **twin pair** (`TWINA`/`TWINB`) — byte-identical research differing only in
  ticker, so any gap between them is pure noise;
- **repeats** at `temperature=0` to size decoding nondeterminism.

The verdict is encoded as code (`_verdict`) so it is not argued after the fact:
between-stock spread < 0.05 → DEGENERATE; twin gap ≥ between-stock spread →
NOISE-DOMINATED; one occupied verdict band → SINGLE-BAND.

## 2. Phase 1 — pin the deterministic guardrails (done)

`backend/tests/test_risk_guardrails.py` (28 tests). The guardrail core had **zero**
coverage before this — `MIN_CONFIDENCE`, `_FLAG_BAND`, `MAX_PER_SECTOR` appeared in
no test — so the property `CLAUDE.md` advertises ("correctness must not depend on
the LLM") was untested. Both sides of both boundaries (0.699/0.70, 0.749/0.75),
`avoid`→REJECT, the sector cap and its unknown-sector exemption, the
highest-confidence-first ordering that decides which names the cap keeps, and the
invariant that a dead note-LLM cannot change a verdict. Verified non-vacuous by
mutation: 8 mutations (threshold shifts, comparison flips, sort reversal, removed
`avoid` check) all killed.

## 3. Phase 2 — give the number a definition (done, code only)

`agents/analyst.py` + `graph/state.py`:

- **Define the proposition.** `confidence` = probability the action is
  directionally right over the horizon (for `buy`, that it outperforms NIFTY 50),
  with verbal anchors (0.50 coin flip / 0.70 a view you'd act on / 0.85+ strong).
- **Split off evidence.** New `evidence_quality` (0–1) and `data_gaps` carry the
  thin-data dimension, so a strong opinion on garbage is distinguishable from a
  strong opinion on good data — the thing the 0.70 gate is really trying to be.
  The earlier plan's "cap confidence when data is thin" instruction was **wrong**:
  both models already sit below the gate, so a ceiling would push them further
  from it. The penalty moved onto `evidence_quality` instead.
- **Reorder `_AnalystOutput`** so both theses + `data_gaps` precede `action`
  precedes `confidence` — the model reasons before it commits, rather than
  rationalising a stance already chosen.
- **Optional new fields with defaults**, so a weaker model that omits them still
  parses instead of raising and getting the stock silently dropped.
- **Silent skip is now logged.** `_analyze_one`'s `except` logged nothing; a
  dropped stock left no trace — the exact empty-run failure `structured()` exists
  to prevent. It now `logger.warning`s with the symbol and error.
- Also wired `time_horizon` through (the schema field the UI already reads was
  never populated).

Tests: `backend/tests/test_analyst_confidence.py` (4) — field mapping, the
omitted-optional-fields landmine, the logged-not-silent skip, and the field-order
regression guard.

## 4. Probe hardening

Three real defects found and fixed in the probe while using it: a double
`asyncio.run` that tore the event loop down under the provider's HTTP client
(`Event loop is closed`); no per-call timeout — B.ai hung one run for 18 minutes;
and a crash on a **total** wipeout — `statistics.fmean` raises on an empty
sequence, so a run where every call failed died in `_render` after printing the
failure table and before writing its JSON. That last one was found by the
OpenRouter 402 above: the one case the probe exists to report was the one case it
could not report. Now one event loop, a configurable `asyncio.wait_for` per call
(`--timeout`, recording a hang as a failure), and a total wipeout renders as
`INCONCLUSIVE — no scores returned`.

# 6. The report — why the desk rejects everything, and the fix

Written after the operator reported *"I am getting rejected for everything even
good stocks"* on the live desk, and added that **an earlier Llama-based Lab did
return buy ratings**. That second remark turned out to be the key to the whole
diagnosis.

## 6.1 What is actually happening

`route_after_risk` (`graph/graph.py`) ends a run before the `execution` node when
every candidate is REJECT. So a full rejection does not merely produce an empty
list — it makes the human-approval pause, the paper watchlist and the approval UI
**unreachable**. The desk looks broken because, end to end, it is.

The gate that rejects them is one line:

```python
if rec.confidence < MIN_CONFIDENCE:      # 0.70
    violations.append("confidence_below_threshold")
```

`confidence` is not a measure of the stock. It is the model's self-report of how
sure *it* feels, and the Analyst is handed almost nothing to be sure from:
`agents/research.py` supplies five price-derived fields (`live_price`,
`day_change_percentage`, `market_cap_cr`, `week52_high`, `week52_low`), a 2–3
sentence summary, and an options strike count. RAG has been dormant since C1, so
`get_relevant_context()` returns `[]` — no earnings, no valuation, no filings.

Asked "what is your probability this beats the NIFTY 50" on a price chart alone,
an honest model answers ~0.55. It will answer ~0.55 for a magnificent business
and for a falling knife, because the question it is being asked is about *its own
certainty*, not about the stock. The 0.70 floor was set as though the number
meant "is this a good pick". **It never did.** Good stocks are not being rejected
*for being bad* — they are being rejected for arriving with thin evidence, which
is every stock this desk has ever looked at.

## 6.2 Why it used to work: the model swap

The operator's memory is correct and it dates the regression precisely.

`a2f2f74` (**2026-08-16**) — *"move Analyst + RiskManager off the decommissioned
`llama-3.3-70b-versatile`"*. Groq decommissioned that model; both agents had it
hardcoded, so the swap to `openai/gpt-oss-120b` was forced and urgent. It was
verified for **schema round-trip** — that `_AnalystOutput` still parsed — which
was the right check for the outage being fixed. Nobody measured whether the new
model *used the confidence scale the same way*, because until B11 there was no
instrument that could.

It does not. Measured on identical fixtures:

| Analyst model | Confidence range | Emits `buy`? | Verdict vs a 0.70 floor |
| --- | --- | --- | --- |
| `llama-3.3-70b-versatile` (pre-2026-08-16) | — (never measured) | **yes, per operator** | some candidates cleared |
| Groq `openai/gpt-oss-120b` (current default) | 0.55–0.65, mode 0.55 | **never** | everything rejected |
| B.ai `glm-5.3-flash` (live via `LAB_MODEL`) | 0.15–0.60 | never observed | everything rejected |

So this is a **silent behavioural regression introduced by a forced model
migration**, not a flaw in the guardrail logic and not a regression from the #73
B.ai swap. The guardrail did exactly what it was told; what changed underneath it
was the meaning of its input.

**In every run the rerun noise is larger than the between-stock spread.**
Scoring the same stock twice moves the number more than swapping a clean-momentum
large cap for a falling knife. Only four distinct values appear across 24 calls at
n=3, and `0.55` accounts for fourteen of them. Across all 139 scores the whole
range is **0.44–0.68**, with 0.55 the mode.

**Correction to §1:** that table records Groq as unaffected by the phase-2 prompt
("0/18"). At n=3 that reproduces exactly — but at n=8 the same model and prompt
produce **13 structured-output failures in 64 calls**, and the unanchored variant
15 in 40. Groq is *less* destabilised than B.ai, not undisturbed; n=18 was simply
too small to see it. Every failure is a stock silently dropped from the run.

This kills "just lower the threshold". There is no cut point: below 0.55
everything passes, at-or-above 0.55 everything rejects, and nothing lives in
between. Retuning the floor converts *rejects everything* into *approves
everything* — the same defect with its sign flipped.

Two fields did survive measurement, and the gate is now built on them:

- **`action` carries the real signal.** MICROVOL (a 19.6% single-day micro-cap
  spike) → `avoid` 3/3. KNIFE (falling knife, near its 52-week low) → `avoid`
  2/3. Every benign setup → `hold` 3/3. The model *can* tell these apart; it
  expresses the distinction categorically, not numerically.
- **`evidence_quality` orders correctly.** NODATA lowest (0.183), CLEANMOM
  highest (0.293). It measures data completeness, honestly — which is why it is
  wired to **flag and never reject** (§6.4).

A corollary worth stating plainly: **no current model ever returns `buy`** — not
even for the clean-momentum large cap. Everything approvable today is a `hold`.
That is defensible for a *watchlist* ("watch this"), but any future change that
gates on `action == "buy"` empties the desk again. `test_hold_is_not_a_rejection`
pins this.

## 6.4 Phase 2's prompt made it worse

The spread has moved in one direction across three measurements of the same
model:

| Groq `gpt-oss-120b` prompt | Between-stock spread |
| --- | --- |
| original (`confidence (0-1)`, no guidance) | **0.320** (twin gap 0.000) |
| B11 phase 2, first run | 0.110 |
| B11 phase 2, this run | **0.043** |

Phase 2 added verbal anchors — *"0.50 is a coin flip, 0.70 a clear view you would
act on, 0.85+ strong"* — and the scores promptly piled up at **0.55**, one notch
above the stated coin-flip value. That is textbook anchoring: the prompt handed
the model a number and the model returned it.

The uncomfortable implication is that the *original* undefined prompt produced a
**more** discriminating number (spread 0.320 against a twin-gap noise floor of
0.000). It was never usable only because the entire range sat below the 0.70
floor — a threshold problem, not a signal problem. Phase 2 fixed the definition
and broke the discrimination.

### The unanchored variant — measured, and it does not rescue the number

Same schema, same fixtures, same model, temperature 0, `--runs 5`; the anchor
sentence replaced with an instruction to use the full range and not to default to
a habitual value:

```
between-stock spread (6 different setups) : 0.058   (anchored: 0.043)
twin gap (identical research, diff ticker): 0.025   (anchored: 0.023)
mean rerun spread at temperature=0        : 0.068   (anchored: 0.050)
band occupancy: {'REJECT': 22, 'FLAG': 0, 'PASS': 0}   failures: 15/40
```

Removing the anchors widened the between-stock spread (0.043 → 0.058) — so the
anchoring effect is real. But it widened **rerun noise further** (0.050 → 0.068),
and rerun noise still *exceeds* the between-stock spread. The number remains
indistinguishable from its own decoding jitter, every score still lands in one
band, and the variant also cost 15 structured-output failures in 40 calls.

Two honest caveats. The variant is **not a clean single-variable test**: it
removed the anchors *and* added a "use the full range" instruction, so the two
effects are confounded. And the probe's `_verdict` compares the between-stock
spread only against the **twin gap**, never against the **rerun spread** — by
that rule this run scores SINGLE-BAND, when the more damning comparison
(0.068 rerun vs 0.058 signal) is the one the verdict does not make. Worth
tightening `_verdict` to treat rerun spread as a noise floor too.

**Conclusion: prompt engineering will not make `gpt-oss-120b`'s confidence
usable.** Anchored or not, the spread sits at or below the model's own rerun
noise. The variable that matters is the *model*, which is why the blocked
`llama-3.3-70b-instruct` probe (§6.6) is the important one. `action` meanwhile
discriminated cleanly again under the unanchored prompt — KNIFE `avoid` 4/4,
MICROVOL `avoid` 5/5, benign setups `hold` — and `buy` still never appeared.

## 6.6 The fix

**Done on this branch:**

1. **The gate rejects for reasons, not for a magic number** (`risk_manager.py`).
   `avoid` → REJECT and the sector cap are unchanged — they discriminate.
   `evidence_quality` **flags but can never reject**, because a hard evidence
   floor would empty the book for precisely the reason the confidence floor did.
   Thresholds moved out of source into `LAB_MIN_CONFIDENCE` / `LAB_FLAG_BAND` /
   `LAB_MIN_EVIDENCE` / `LAB_MAX_PER_SECTOR`, so the next forced model migration
   is a config change rather than a silent behavioural regression. Malformed
   values fall back loudly.

   **The shipped defaults, set from the 139 measured scores:**

   | Constant | Value | Why |
   | --- | --- | --- |
   | `MIN_CONFIDENCE` | **0.40** | *Below* the lowest score ever observed (0.44), so nothing legitimate rejects on confidence alone. A collapse detector for a broken model, not a quality bar — because the number provably cannot rank stocks. |
   | `_FLAG_BAND` | **0.70** | *Above* the highest score ever observed (0.68), so every recommendation from the current model is a FLAG, never a clean PASS. On price-and-52-week-range input there is no high-conviction call to be had, and a PASS badge would claim a confidence the measurement does not support. |
   | `MIN_EVIDENCE` | **0.35** | *Above* the highest `evidence_quality` observed (0.30), so `thin_evidence` fires on essentially every call while RAG is dormant. That is the true state of the data; it stops firing on its own once C1 lands. |

   Two of these are deliberately chosen to be *unreachable* by the current model.
   That is the honest expression of a degenerate signal: the gate stops
   pretending to rank, `action` and the sector cap do the rejecting, and every
   survivor arrives labelled as what it is — a low-conviction call on thin data
   that a human must judge. A model with real spread earns `PASS` back by moving
   one env var.
2. **A wipeout now explains itself.** When every candidate fails on confidence
   alone — no `avoid`, no full sector — `rejection_reason` says so, quotes the
   best score against the floor, and names the probe and the env var. That is the
   message that should have been on screen instead of a silent rejection.
3. **Honest presentation** (`RecommendationCard`, `ApprovalModal`,
   `StatusBadge`). The bar is labelled **Conviction**, not Confidence, and says
   in the open that it is a model self-assessment and not a calibrated
   probability. `evidence_quality` is drawn beside it, `data_gaps` are surfaced,
   and the approval modal — the last thing read before approving — shows the
   conviction/evidence pair rather than a lone percentage. Risk tooltips no
   longer quote thresholds the frontend cannot see.
4. **Tests.** 26 new backend tests (7/7 mutations killed, including "evidence
   becomes a violation" — the bug reintroduced) and 6 frontend tests.

**Bake-off status:** `qwen/qwen3.8-27b` measured (below — the current
recommendation), higher-n Groq and the unanchored prompt measured (§6.3–6.4),
B.ai `glm-5.3-flash` measured (below — the revised recommendation),
`llama-3.3-70b-instruct` blocked on billing.
Then: pick the
Lab analyst model on measured discrimination **and** on whether it ever says
`buy`, set the four thresholds from its distribution, and pin the choice with the

### The real B.ai risk is latency, not correctness

The 24-call probe took **27.5 minutes — roughly 68 seconds per call**. Two
consequences, neither of them addressed by this card:

1. **`agents/analyst.py` analyses candidates sequentially** (`for report in
   state.research_reports.values()`). At ~68s per call, five candidates is ~5.7
   minutes in the Analyst node alone, before the scanner, research and risk nodes.
   `agents/research.py` already uses `asyncio.gather`; the Analyst should too.
2. **Production has no per-call timeout at all.** The probe bounds each call with
   `asyncio.wait_for`; the Lab does not. A call that hangs — and B.ai demonstrably
   exceeds 90s — hangs the whole run with no upper bound. The probe's own
   `_CALL_TIMEOUT_S` is the pattern to copy into `get_lab_llm`.

Both belong in a follow-up card. They are the likely reason a Lab run *feels*
broken even once the gate is fixed.

## 6.7 What this fix does *not* do

It does not make the number predictive. Phases 2–4 make it better-defined,
better-presented and no longer load-bearing for a decision it cannot support;
none of that is calibration. Only **phase 5** — re-pricing watchlist symbols at
+1w/+1m/+3m against stored confidence and fitting isotonic regression — would
earn the word, and it stays in the backlog. Until then the card says
"self-assessment, not calibrated" because that is exactly what it is.

The deeper constraint is upstream and unchanged: an analyst given only price and
a 52-week range cannot form a well-founded view, whatever number it reports. The
real ceiling on this desk is **C1** (re-enable the RAG corpus) and richer
fundamentals from the MCP — not the gate.
