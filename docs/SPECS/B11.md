# B11 — Lab confidence: make the number mean something (or stop drawing it as a bar)

**Status:** phases 0–2 done on a branch; phases 3–5 pending a Lab-analyst model
decision (see §5). Not on `main`, not deployed. This is exploratory hardening of
the Lab (a labelled simulation on a paper watchlist), **not** investment advice —
V2_PLAN §8.3 bars instrument-level advice on real holdings and nothing here
touches the portfolio side.

## 0. The problem

`AnalystRecommendation.confidence` (`agents/analyst.py`) is an LLM self-report.
The entire specification the model received was the token `confidence (0-1)` and
the schema description `"Confidence 0-1."` — nothing defined confidence *in what*,
over what horizon, against what evidence. That number then drives all three risk
verdicts (`agents/risk_manager.py`), sorts the per-sector cap, persists
denormalised into `watchlist`, and renders as a filled `ConfidenceBar` in
`components/RecommendationCard.tsx`.

## 1. Phase 0 — measurement (the gate)

`backend/evals/confidence_probe.py` scores the **real** Analyst path
(`_build_prompt` + the same `structured()` binding, minus the `except: return
None` that hides failures) over a fixed synthetic fixture set. It is deliberately
**not** a pytest test — `tests/conftest.py` scrubs provider keys (issue #31), so a
probe needing a real key cannot live there. Fixtures are synthetic (no user data);
run it with `python -m evals.confidence_probe`.

The design measures **signal vs noise**, not just a histogram:
- a **contrast set** of six setups an analyst should feel differently about;
- a **twin pair** (`TWINA`/`TWINB`) — byte-identical research differing only in
  ticker, so any gap between them is pure noise;
- **repeats** at `temperature=0` to size decoding nondeterminism.

The verdict is encoded as code (`_verdict`) so it is not argued after the fact:
between-stock spread < 0.05 → DEGENERATE; twin gap ≥ between-stock spread →
NOISE-DOMINATED; one occupied verdict band → SINGLE-BAND.

### Findings (synthetic fixtures; live end-to-end run still pending, §5)

| Model | Prompt | Structured failures | Confidence range | Between-stock spread | Twin gap | `evidence_quality` | Verdict band |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Groq `gpt-oss-120b` | original | 0/18 | 0.30–0.62 | 0.320 | 0.000 | (n/a) | **all REJECT** |
| Groq `gpt-oss-120b` | B11 (post) | 0/18 | 0.52–0.63 | 0.110 | 0.043 | 0.20–0.29 | **all REJECT** |
| B.ai `glm-5.3-flash` | original | 0/18 | 0.15–0.60 | 0.383 | 0.050 | (n/a) | **all REJECT** |
| B.ai `glm-5.3-flash` | B11 (post) | **11/16** | 0.55–0.60 | 0.050 | — | 0.10–0.30 | **all REJECT** |

Three conclusions:

1. **The original bug is real and pre-existing.** Every cell is all-REJECT
   against the 0.70 gate — independent of model *and* prompt. No candidate of this
   shape came within ~0.08 of 0.70, so `route_after_risk` (`graph/graph.py:35`)
   ends the run before the `execution` node: the human-approval pause, the paper
   watchlist and the approval UI are all unreachable. This is a standing
   mismatch, not a regression from #73's B.ai swap.
2. **The Phase 2 design works where the model responds.** Both models now report
   `evidence_quality` honestly (0.10–0.30 on thin data; `NODATA` correctly the
   floor), separated from directional conviction.
3. **The richer Phase 2 prompt destabilises the production model.** B.ai
   `glm-5.3-flash` — the live Lab model (#73) — went from 0/18 to **11/16
   failures with 90s+ timeouts** under the longer prompt. Groq is unaffected
   (0/18). In the probe these surface as errors; in production the Lab has no
   per-call timeout, so they would *hang* the run. The #73 bake-off picked B.ai
   on a simpler prompt and did not test this.

## 2. Phase 1 — pin the deterministic guardrails (done)

`backend/tests/test_risk_guardrails.py` (28 tests). The guardrail core had **zero**
coverage before this — `MIN_CONFIDENCE`, `_FLAG_BAND`, `MAX_PER_SECTOR` appeared in
no test — so the property `CLAUDE.md` advertises ("correctness must not depend on
the LLM") was untested. Both sides of both boundaries (0.699/0.70, 0.749/0.75),
`avoid`→REJECT, the sector cap and its unknown-sector exemption, the
highest-confidence-first ordering that decides which names the cap keeps, and the
invariant that a dead note-LLM cannot change a verdict. Verified non-vacuous by
mutation: 8 mutations (threshold shifts, comparison flips, sort reversal, removed
`avoid` check) all killed.

## 3. Phase 2 — give the number a definition (done, code only)

`agents/analyst.py` + `graph/state.py`:

- **Define the proposition.** `confidence` = probability the action is
  directionally right over the horizon (for `buy`, that it outperforms NIFTY 50),
  with verbal anchors (0.50 coin flip / 0.70 a view you'd act on / 0.85+ strong).
- **Split off evidence.** New `evidence_quality` (0–1) and `data_gaps` carry the
  thin-data dimension, so a strong opinion on garbage is distinguishable from a
  strong opinion on good data — the thing the 0.70 gate is really trying to be.
  The earlier plan's "cap confidence when data is thin" instruction was **wrong**:
  both models already sit below the gate, so a ceiling would push them further
  from it. The penalty moved onto `evidence_quality` instead.
- **Reorder `_AnalystOutput`** so both theses + `data_gaps` precede `action`
  precedes `confidence` — the model reasons before it commits, rather than
  rationalising a stance already chosen.
- **Optional new fields with defaults**, so a weaker model that omits them still
  parses instead of raising and getting the stock silently dropped.
- **Silent skip is now logged.** `_analyze_one`'s `except` logged nothing; a
  dropped stock left no trace — the exact empty-run failure `structured()` exists
  to prevent. It now `logger.warning`s with the symbol and error.
- Also wired `time_horizon` through (the schema field the UI already reads was
  never populated).

Tests: `backend/tests/test_analyst_confidence.py` (4) — field mapping, the
omitted-optional-fields landmine, the logged-not-silent skip, and the field-order
regression guard.

## 4. Probe hardening

Two real defects found and fixed in the probe while using it: a double
`asyncio.run` that tore the event loop down under the provider's HTTP client
(`Event loop is closed`), and no per-call timeout — B.ai hung one run for 18
minutes. Now one event loop and a 90s `asyncio.wait_for` per call, recording a
hang as a failure.

## 5. Pending — needs a decision, then data

- **Phase 3 (thresholds).** 0.70/0.75 are hardcoded constants that match neither
  model on thin data. They must be set from a measured distribution — but on
  *which* model. The operator will supply a Lab-analyst model/key; re-run the
  probe against it, then set the thresholds (and decide whether the gate should
  read `evidence_quality`, not confidence alone).
- **Phase 4 (honest presentation).** Relabel `ConfidenceBar` as a model
  self-assessment and surface `evidence_quality` beside it; fix the `StatusBadge`
  tooltips if the thresholds move. If Phase 0 had come back DEGENERATE this would
  be the *whole* fix; it came back SINGLE-BAND, so it rides alongside Phase 3.
- **Phase 5 (real calibration) — BACKLOG.** Re-price watchlist symbols at
  +1w/+1m/+3m, store returns against stored confidence, fit isotonic regression.
  This is the *only* step that is actually calibration; phases 2–4 make the raw
  number better-behaved but still uncalibrated, and the card must say so.

### Carried landmines

- **`method="function_calling"` must survive** — `tests/test_llm_routing.py`
  fails the build on a direct `with_structured_output`.
- **Old `watchlist` rows become incomparable** once the number's meaning changes;
  denormalised on purpose, never migrated. Accept and document, or add a
  `confidence_basis` marker.
- **The live IND Money token is a placeholder** (`.ind_money_token.json`, redacted
