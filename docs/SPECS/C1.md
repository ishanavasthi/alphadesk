# C1 — Unplug RAG, slim the image, pin deps, retire the screenshot binaries

Branch: `chore/slim-image` (off `main` @ `7c06590`).
Scope: build/config/docs only. **Zero Python changed.**

## What this card did, and why

Three production landmines, one branch:

1. **The image carried a RAG stack that does nothing.** `data/nse_docs/` is
   empty (0 bytes of PDFs) and `data/chroma_db/` was a 184K empty collection.
   The Analyst has been running with no filing context all along — so chromadb,
   its `build-essential` apt layer and the ONNX embedding-model download were
   pure image weight with zero behavioral contribution.
2. **Dependencies were unpinned.** Only `mcp` was pinned, and only *after*
   `mcp` 2.0.0 removed `mcp.client.streamable_http.streamablehttp_client` and
   killed prod at import. Every other dep had the same failure mode armed: any
   rebuild of the Space could silently install a new major.
3. **Two PNGs in `docs/screenshots/` tripped Hugging Face's binary policy**,
   which forced every deploy through a `space-deploy` snapshot branch instead
   of a plain `git push space main`.

**Pin policy (the contract this card establishes):** every direct dependency is
pinned to an exact version. A version bump is a deliberate, standalone commit
with its own verification — never a side effect of a rebuild. Adding a new dep
means adding it pinned.

## Why removing chromadb is behavior-neutral

`backend/rag/retriever.py` already degrades gracefully. `_get_collection()`
wraps the `import chromadb` **inside** the `try`, and any exception sets
`_init_failed = True` and returns `None`; `get_relevant_context()` then returns
`[]`. A missing chromadb is indistinguishable, to the Analyst, from an empty
collection — which is what it had before this card anyway.

The Analyst is the only consumer, and it treats an empty context as normal:
verified end-to-end on this branch (see `docs/TESTING/C1.md`) — a full pipeline
run produced five complete analyst recommendations with `citations: []`.

## Re-enabling RAG

1. Add back to `requirements.txt`, pinned:
   `chromadb==1.5.9`, `pypdf==6.14.2`, `langchain-text-splitters==1.1.2`
   (the versions that were in the venv when this card ran).
2. Put PDFs in `data/nse_docs/`.
3. Locally: `cd backend && python -m rag.ingest` → builds `data/chroma_db/`.
4. In the `Dockerfile`, restore the three removed pieces:

   ```dockerfile
   RUN apt-get update && apt-get install -y --no-install-recommends \
       build-essential \
    && rm -rf /var/lib/apt/lists/*
   ...
   COPY data/ ./data/
   RUN cd backend && python -m rag.ingest || true
   ```

   Expect the image to grow substantially and the build to slow down — the
   onnxruntime wheel plus the MiniLM model download are the bulk of it.
5. No Python changes are needed at any step; the retriever picks the collection
   up on its next call.

## Notes / caveats

- `data/` still exists in the repo (empty `nse_docs/`, gitignored
  `chroma_db/`); only the Docker `COPY` of it was removed. Host-side RAG work
  is therefore unaffected.
- The repo-root venv still has chromadb/pypdf/langchain-text-splitters
  installed from before. That is fine — they are simply unused, and the Docker
  build is the authority on what production installs.
