# F4 — Per-user Lab state, and the last ambient path closed

Branch: `v2-foundation` (off `main` @ `35017a4`, after F3).

Owns: `backend/api/main.py` (the Lab endpoints + their in-memory state),
`backend/graph/state.py` (a `user_id` on the run), `backend/tools/ind_money_auth.py`
(the run-user binding), `backend/db/models.py` + `alembic/versions/0005_*`
(the `watchlist` table), `frontend/app/lab/` (the desk, moved), tests, docs.

The Lab is a labelled *simulation*, so it does **not** get a persistence layer —
its runs live in memory and are lost on restart, by decision (plan §2, §6). This
card does three things around that decision: it threads a real per-user identity
through the Lab, it closes the one ambient credential path F3 left open
(`POST /analyze`), and it persists the **one** thing that must outlive a run —
the paper watchlist.

---

## 1. Identity on the run — `PortfolioState.user_id`

`PortfolioState` gains an explicit `user_id` (default `"local"`), stamped at run
creation from the caller's verified identity. It is not decoration: the pipeline
reaches the IND Money MCP through `tools/ind_money.py`'s **market-data** tools,
which take no user in their signature (they ask for quotes and movers, not
anyone's holdings). So the caller's identity is carried to them out of band —
see §3 — and `PortfolioState.user_id` is the in-band record of whose run it is.

## 2. In-memory Lab state, keyed by user

`_RUNS`, `_ANALYSES` and `_ACTIONS` stay in memory (the `MemorySaver`
checkpointer is unchanged — no Postgres checkpointer, no `runs`/`analyses`
tables) but every record now carries the `user_id` it belongs to, and every read
is scoped to the caller through one helper:

```python
def _owned_run(run_id, user_id, registry) -> record | 404
```

A record whose owner is not the caller is a **404, not a 403** — a 403 would
confirm the id is real (plan §7). `/analyses` filters to the caller; `/approve`,
`/analysis/{id}` and `/status/{id}` each resolve through `_owned_run`. A paused
approval lost to a restart is an accepted trade, and the UI says so (§6).

## 3. The last ambient path closed — `POST /analyze` (F3 carry, REQUIRED)

Before F4, `/analyze` was **ungated** and ran on `ind_money_auth.ambient_user_id()`
— the operator in production, `"local"` in single-tenant dev. An anonymous
request therefore burned Groq *and* read whichever grant the ambient path
resolved to. This was the last ambient credential path, ledgered as REQUIRED in
F3 §11.0.

F4 closes it. Every Lab endpoint takes `_lab_identity`:

- a verified Clerk session token → that user;
- **no** token in single-tenant dev (`ALPHADESK_SINGLE_TENANT=1`) → `"local"`,
  the operator's own machine, exactly as linking already works;
- otherwise → **401**. There is deliberately **no interim admin-secret path**
  here (unlike `/portfolio/*`): an admin-header Lab run would be the unowned,
  ambient run this card removes.

`/analyze` then checks **that user's** link — `auth_status(user_id)`, not the
process's — and answers **409** ("link your IND Money account to run the Lab")
for an unlinked caller. Every agent downstream of the Scanner is fed by the MCP,
so an unlinked run can only produce an empty "0 candidates" pipeline that looks
real; running one would also spend the ambient grant.

**The pipeline runs as the caller.** `analyze()` binds the verified `user_id`
into a `ContextVar` (`ind_money_auth.bind_run_user`) for the life of the run and
resets it in `finally`. `ambient_user_id()` reads that binding first, so the
userless MCP tool calls the graph makes mint from *this* user's `AuthStore` —
never a process-wide or "whoever linked first" grant. A `ContextVar` (not a
module global) because each asyncio task the graph spawns inherits a snapshot of
the context it was created in, so concurrent runs never cross, and the reset
guarantees a later userless call falls back to the ambient identity rather than
the last Lab caller. `/approve` binds the same identity around its resume, since
the Execution node also reaches the MCP.

`ambient_user_id()` is **kept, not deleted**: `tools/ind_money.py`'s market-data
tools still call it as their fallback for genuinely userless callers. Its
docstring and the `analyze()` pointer were updated; the F3 §11.0 ledger line is
struck.

## 4. The paper watchlist persists — `watchlist` table

The one durable exception. New table (migration `0005`), **denormalized**: each
row is a self-contained decision record frozen at approval —

```
watchlist  user_id FK (ON DELETE CASCADE) | symbol | company | thesis
           | confidence | action | risk_verdict | query
           | run_id (opaque, non-FK) | added_at
           PK (user_id, symbol)
```

Why denormalized and not a join back to the run: a Lab run is gone after a
restart, so a normalized reference would leave every watchlist row unreadable
the first time the process bounces. `run_id` is kept as an **opaque, non-FK**
column — there is no `runs` table for it to reference — so "view the original
run" resolves it while the run is still in memory (`run_available: true`) and
degrades to "this run is no longer available" (a **404** from `/analysis/{id}`,
which the frontend already renders) when it is not. Never a broken FK, never a
silent recompute.

`PK (user_id, symbol)` with `ON CONFLICT DO NOTHING`: a stock a user already
holds keeps its **first** decision. The FK cascades with `users` at the DB level
(`confdeltype = 'c'`, verified) — L1's delete-my-data depends on it.

Writes go through `_persist_watchlist(session, user_id, rows)`; reads through
`read_watchlist(session, user_id)`; both fall back to a per-user in-memory dict
when `DATABASE_URL` is unset, so single-tenant local dev with no Postgres keeps
working (the dashboard already degrades this way — CLAUDE.md). `ensure_user_row`
is called before a write so the FK resolves for a `"local"` caller that never
went through a Clerk upsert.

## 5. The desk moved to `/lab`

`frontend/app/page.tsx` → `app/lab/page.tsx`; `app/a/[id]` → `app/lab/a/[id]`.
The root `/` now `redirect()`s to `/lab` so old links keep working (U1 owns the
real landing). Every `/lab` view carries a persistent banner — *"Lab — a live
simulation. Runs aren't saved. Not investment advice; no orders are placed."* —
placed in `app/lab/layout.tsx` so no page can render without it. The Bloomberg
terminal aesthetic is untouched (no shadcn restyle — plan §2); the D1
`/portfolio` surface keeps its own shadcn chrome, and `TerminalChrome` still
shows the terminal `TopBar` on the Lab. Route references (`ResultsDashboard`
`replaceState`, `AnalysisView` and the not-found link) updated to `/lab`.
`WatchlistItem` in `lib/api.ts` gained the denormalized fields (all optional, so
the `WatchlistButton` still compiles).
