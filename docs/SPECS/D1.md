# D1 — Portfolio dashboard (API + `/portfolio`)

Branch: `feat/portfolio-dashboard` (off `main` @ `f6a0949`, after the D0 design gate).
Scope: `backend/api/routes/portfolio.py` (new), `frontend/app/portfolio/` (new),
`frontend/components/portfolio/` (new), plus three minimal edits elsewhere —
mounting the router in `api/main.py`, additive fetch helpers in
`frontend/lib/api.ts`, and one conditional in `frontend/app/layout.tsx` (§6).

This card turns M1's connector into something a person can look at. Everything
it renders comes from a source call; nothing on the page is computed to fill a
gap, and the states that exist *because* data is missing are as designed as the
states where it is present.

---

## 1. The API

Four routes under `/portfolio`, all `GET`, all read-only, all gated (§2).

| Route | Source calls | Returns |
| --- | --- | --- |
| `/portfolio/summary` | `link_health` + `fetch_snapshot` | Totals, P&L, the snapshot's four breakdowns, `link_health`, `last_captured_at: null` |
| `/portfolio/holdings?asset_type=` | `fetch_holdings` (one type) | `{asset_type, currency, holdings: [...]}` |
| `/portfolio/allocation?asset_type=&by=` | `fetch_allocation` (one slice) | `{asset_type, by, slices: [...]}` |
| `/portfolio/history?days=` | none | `{points: [], last_captured_at: null, days, note}` |

### Decimal serialization: **strings**

Every money and percent field is a JSON **string** (`"1152655.0"`, `"8.36"`),
never a number. JSON has no decimal type; a `Decimal` that goes out through a
float comes back having lost exactly the trailing digits a tabular figure is
judged on. The frontend parses with `Number()` where it needs arithmetic and
prints the string otherwise. `null` stays `null` and never becomes `0` — that
distinction is the whole point of M1's cost-basis rule.

The string also preserves the source's own precision verbatim: `"12000.0"` is
what the source said, and normalizing it to `"12000"` would be this layer
deciding how many digits the source meant.

### `/summary` carries four breakdowns, not one

`fetch_snapshot` returns `by_asset_type`, `by_asset_class`, `by_sector` and
`by_market_cap` in **one** call, so the summary passes all four through. That is
what feeds the dashboard's sector card and cap-band strip at zero extra
rate-limit cost.

`/portfolio/allocation` remains for the **per-asset-type drill-down**, which is
the only thing the source's breakdown tool can actually answer (it requires an
asset type). It is fetched lazily, one `(asset_type, by)` pair per user click.
**The 16×3 grid is never swept**: at cost 2 per breakdown against a 15/min
per-tool budget it would trip after seven calls.

*(Ruling recorded at the D1 gate: the split above was approved by the
orchestrator over the brief's original "sector comes from the allocation
endpoint", because the snapshot's portfolio-wide sector figures are free and are
what `a-shadcn.html` actually draws.)*

### `last_captured_at` and `/history`

Both are honestly empty until card S1 captures the first daily snapshot. The
`/history` response shape is final — S1 fills `points` with
`{date, net_worth}` objects and sets `last_captured_at`; neither the route nor
the chart component changes. Returning a synthesized series here would be
inventing a past this deployment does not have.

### Nothing vendor-shaped crosses the boundary

No vendor field name appears in `api/routes/portfolio.py`, and `Holding.raw` /
`AllocationSlice.raw` are **not serialized**. `raw` exists for forensics below
the connector boundary; shipping it to a browser would put the vendor's own key
names (and any unmapped material) back above it.

## 2. The interim exposure gate — and how F3 removes it

**Every `/portfolio/*` route requires the `x-alphadesk-admin-secret` header**
matching `ALPHADESK_ADMIN_SECRET`. Without it: **401**.

The router declares `dependencies=[Depends(_admin_gate)]`, and `_admin_gate`
calls `api.main._require_admin` — the same C0 gate as `/auth/login` and
`/auth/logout`, deliberately not a second implementation. (The import is
deferred inside the function because `api.main` mounts this router; a
module-level import would be circular.)

Why a read-only route needs a gate: until F3 there is **no user identity in the
stack**. These routes serve the operator's real holdings under the constant
`user_id="local"`, so an ungated deployment publishes one person's net worth to
anyone who can reach the URL.

Inherited from C0, deliberately: `ALPHADESK_SINGLE_TENANT=1` **bypasses** the
gate. That is the operator's own machine, where the process already holds their
credentials, and it is what keeps the in-app Connect button working locally. It
must stay unset in every deployed environment. Both modes are pinned by tests
(§5) so neither can drift.

**F3 removes all of this**: per-user auth replaces the shared secret, the
`user_id` argument stops being a constant, and `_admin_gate` and the frontend's
`LockedState` are deleted together.

### Typed source failures → HTTP

| Exception | Status | `detail.code` | Frontend state |
| --- | --- | --- | --- |
| `NotLinked` | 409 | `not_linked` (+ `connect` hint) | Connect gate |
| `RateLimited` | 429 | `rate_limited` (+ `retry_after`, `Retry-After` header) | Quiet inline wait, one retry |
| `UnsupportedAssetType` | 400 | `unsupported_asset_type` | Dashed source-empty callout |
| `UserScopeError` | 403 | `user_scope` | Source-error screen |
| `UnverifiedShapeError` | 502 | `unverified_shape` | Labeled boundary callout |
| `NonInrValue` | 502 | `non_inr` | Source-error screen |
| `PayloadShapeError` | 502 | `payload_shape` | Source-error screen |
| `SourceUnavailable` / `SourceReportedError` | 502 | `source_unavailable` | Source-error screen |
| unknown asset type / breakdown in the query | 400 | `unknown_asset_type` / `unknown_breakdown` | — |

Two properties hold across the table:

- **A source failure never surfaces as a 500.** Every route catches
  `PortfolioSourceError`, which M1 guarantees is the only thing a connector
  raises.
- **The message is ours, never the source's.** Messages are fixed strings; a
  source's error body can quote payload fragments, and this response is public
  to everyone past the gate. A test asserts a source-supplied token never
  appears in a response body.

`UnsupportedAssetType` is a **400, not a 502**, because it describes the request
rather than the source's health: the snapshot reports buckets (e.g.
`US_STOCK_WALLET`) that the holdings endpoint's enum refuses. The dashboard
reads that 400 as "this bucket cannot be enumerated" and renders the dashed
callout — the EPF pattern.

### Choosing a connector

`ALPHADESK_PORTFOLIO_SOURCE=stub` swaps `IndMoneyConnector` for
`StubConnector` (the invented portfolio in `backend/tests/fixtures/demo/`).
Default is IND Money. **The stub path is the only safe way to screenshot this
dashboard** — see `docs/TESTING/D1.md`. The connector is a module-level
singleton because `IndMoneyConnector` remembers a definitive revocation, and
that memory is worthless if every request builds a fresh instance.

### Honesty rules the components enforce

- **Return is `pnl_pct`, and there is no XIRR.** C2 killed it: the vendor's own
  field was `0` in 14 of 14 rows and no dated cashflow exists anywhere in the
  API. `—` renders whenever the basis is unknown, with the tooltip "Cost basis
  not reported by the source"; a real wipe-out (basis known, value 0) shows an
  honest −100%.
- **Totals are the source's, never a sum of the table.** They do not reconcile
  and nothing asserts that they do (M1 §5). The stat card's note says "across N
  holdings", and while buckets are still loading it says "loaded so far".
- **US exposure is a badge, not a currency.** No payload carries a currency
  field; the signal is the asset type.
- **Nulls sort last** in both directions — "not reported" is not a small number.

## 4. Tailwind / shadcn integration

**The brief expected a greenfield frontend; the repo already had Tailwind
3.4 + `components.json`** (style new-york, base colour **neutral**, radius
**0.25rem**) driving the dark Bloomberg terminal on `/` and `/a/[id]`.
Re-initialising shadcn at zinc / 0.5rem globally would have restyled two shipped
pages nobody asked to change.

So the DECISION token set is **scoped**, not global:

- `frontend/app/portfolio/portfolio.css` redeclares the shadcn CSS variables on
  the `[data-adp]` attribute — the DECISION palette as HSL triplets, radius
  0.5rem, system sans. Inside that subtree `bg-card`, `border-border`,
  `rounded-lg` resolve to the zinc light theme; everywhere else they still
  resolve to the terminal's.
- Extras the shadcn token set has no slot for (`--adp-accent`, `--adp-good`,
  `--adp-bad`, the cap ramp, the warn triple) are plain CSS variables used
  through Tailwind's arbitrary-value syntax.
- `frontend/app/portfolio/layout.tsx` is the only place `data-adp` is set, and
  its `min-h-screen bg-background` is what covers the root body's near-black.
- `frontend/components/portfolio/ui.tsx` carries this surface's shadcn
  primitives. The existing `components/ui/*` are terminal-tuned (uppercase mono
  buttons, 4px radii) and editing them in place would change `/`. Copying and
  editing components is how shadcn is meant to be used.
- Tailwind's preflight was already applied app-wide before this card and is
  unchanged; the legacy pages are byte-identical apart from §6.

**Flipping the app-wide default to the DECISION tokens is U1's call, not D1's.**

## 5. Tests

`backend/tests/test_api_portfolio.py`, no network — the connector is injected
through FastAPI's dependency override.

- **The gate, in both modes.** Every route × {no header, wrong header, right
  header} = 401/401/200; the secret unset → 401 (fail-closed, never open);
  `ALPHADESK_SINGLE_TENANT=1` → bypass, marked local-only.
- **The error mapping**, one case per exception type, asserting status *and*
  `detail.code`; the 429 case asserts `Retry-After` and the parsed
  `retry_after`; the 409 case asserts the `connect` hint; one test asserts a
  source-supplied string never reaches the response body.
- **Response shapes** against the stub: money as strings, `pnl`/`pnl_pct` null
  where the basis is unknown, the genuine −100% row intact, `raw` absent, the
  `UNKNOWN` bucket keeping `asset_type_raw` and its US-exposure flag, empty
  buckets returning `[]` rather than an error, `/history` honestly empty.

Frontend verification (typecheck, build, screenshots, curl matrix, live sanity
calls) is in `docs/TESTING/D1.md`.

## 7. Where the design and the source disagree

Two places the reference pages could not anticipate, both resolved in code and
flagged here:

1. **Cap bands: the design drew three, the live source returns four** —
   `Mega Cap`, `Large Cap`, `Mid Cap`, `Small Cap` (the demo fixture has three).
   Cycling the locked three-colour ramp would give the fourth band the *darkest*
   colour and destroy the one thing a sequential ramp asserts. `capRamp(n)`
   samples the piecewise-linear gradient between the locked stops instead, which
   keeps lightness monotonic for any band count and reproduces the locked three
   exactly when there are three. Ordering is `mega → large → mid → small →
   micro/nano`, with anything unrecognised keeping the source's own order.
2. **Sector drill-down chips.** The reference sector card has no controls; the
   real breakdown tool is per-asset-type only. The card therefore shows the
   portfolio-wide snapshot figures by default, with a chip row ("Whole
   portfolio" + each asset type present) that fetches one slice per click. Chips
   are offered for every asset type the snapshot reports, including ones likely
   to answer empty — the alternative was hard-coding a guess about which asset
   types have sectors.

## 8. What D1 deliberately does not do

- **No writes.** Every route is a `GET`; nothing persists.
- **No snapshots.** History is S1's; the chart and the API shape are ready for
  it and say so.
- **No AI overview** (`a2-overview.html`), **no insights page**
  (`a3-insights.html`), **no landing / demo / lab surfaces**
  (`a4-shell.html`) beyond the connect gate — those are later cards' surfaces.
- **No navigation into `/portfolio`.** The route is reachable directly and is
  not linked from `/`; U1 wires the shell.
- **No new backend dependency.** Frontend adds exactly one: `recharts`.
