# A1 — AI overview (multi-agent, numbers-computed-in-Python)

Branch: `feat/ai-overview` (off `main` @ `7ae2eb2`, after F4).

Owns: `backend/agents/portfolio/` (new), `backend/graph/portfolio_graph.py` (new),
`backend/agents/llm.py` (extended), `backend/api/routes/overview.py` (new),
`backend/tests/fixtures/demo/overview.json` (the committed demo artifact),
`frontend/components/portfolio/AiOverview.tsx`, `frontend/lib/api.ts`,
`frontend/app/portfolio/page.tsx`, tests.

The dashboard's narrative layer, built around one ironclad rule:

> **Numbers are computed deterministically in Python. The agents narrate
> verified metrics and may not invent a single figure. The dashboard renders
> completely when the LLM is unavailable — that is a hard requirement.**

---

## 1. Deterministic metrics — `agents/portfolio/metrics.py`

`compute_metrics(snapshot, holdings, *, history=None, sips=None) -> list[Metric]`.
Every number the overview can ever show is computed here from the **verified M1
model** (`portfolio.models`), before any agent runs. A `Metric` is a typed value
with a **stable key**, a canonical `display` string (the exact text the narrative
chip renders), a raw `value`/`text`, an `available` flag, and a short `detail`.

### The metric keys

| Key | Unit | Definition |
| --- | --- | --- |
| `net_worth` | inr | Snapshot net worth (net of liabilities), source's own figure. |
| `current_value` | inr | Snapshot gross value. |
| `invested_total` | inr | Snapshot invested total; `available=False` when the source reports none. |
| `pnl` | inr | `gross − invested`, **only** when a cost basis exists; else unavailable (never a fabricated 0/−100%). |
| `pnl_pct` | pct | `pnl / invested × 100`. The simple return — **never labelled XIRR** (C2 killed XIRR). |
| `holdings_count` | count | Number of holding rows. |
| `rows_without_cost_basis` | count | Rows with `invested_amount is None`, detail `of N`. |
| `herfindahl_index` | ratio | Σ(weightᵢ²) over holding weights (denominator = Σ holding values). Band: diversified <0.15 ≤ moderate <0.25 ≤ concentrated. |
| `top_holding_weight` | pct | Largest single holding's share of held value; detail = its name. |
| `top_holding_name` | text | Largest position's display name. |
| `top3_weight` | pct | Top-3 holdings' combined share. |
| `equity_share` | pct | (IND_STOCK + US_STOCK + US_STOCK_WALLET current value) ÷ gross. |
| `us_exposure_share` | pct | Foreign-denominated buckets ÷ gross (M1's US-exposure signal). |
| `heaviest_sector_weight` | pct | Heaviest `by_sector` slice's share of the sector book; detail = its label. |
| `heaviest_sector_name` | text | Heaviest sector label. |
| `sector_hhi` | ratio | Herfindahl over sector weights (concentration). |
| `sector_count` | count | Sectors with a value. |
| `sip_count` | count | SIP rows on file; detail `N active`. |
| `sip_monthly_total` | inr | Sum of **active** SIP amounts. |
| `wow_networth_delta` | inr | Latest net worth − the S1 snapshot closest to 7 days prior (window 4–11 days). |
| `wow_networth_delta_pct` | pct | Same as a percentage. |

**Weights and concentration are computed over the holding rows we actually
have** (denominator = their summed value), never over the snapshot headline — the
two do not reconcile by construction (M1 §5). Allocation-share metrics come off
the snapshot's own breakdown slices, which is where those buckets are enumerated.

### The three degenerate portfolios (each pinned by a test)

- **one holding** → HHI `1.00`, top weight `100.0%`, band "concentrated" — a real
  warning, not a crash;
- **no `invested_amount` anywhere** → `pnl`/`pnl_pct`/`invested_total` all
  `available=False`, so the overview makes **no performance claim** rather than a
  fabricated one;
- **empty** → concentration metrics degrade to unavailable (`—`), never a
  division by zero.

There is **no XIRR** and no forward projection anywhere — descriptive only (§8).

## 2. `redact()` — `agents/portfolio/redact.py` (§8.1)

Every prompt payload is routed through `redact()`. It denies by key (account
numbers, broker ids, emails, the Clerk `user_id`, tokens/secrets, vendor
instrument ids, …, matched on a separator-stripped key) **and** by value (an
email- or opaque-id-shaped string is dropped even under an innocent key). It
walks arbitrarily nested dicts/lists and fails safe. A test feeds it a payload
carrying every forbidden class at once and asserts `contains_pii()` is false
while the allowed aggregates and instrument symbols survive.

The metric catalog the agents receive is clean by construction (aggregates +
instrument names only); `redact()` is the belt-and-braces gate on top.

## 3. The multi-agent graph — `graph/portfolio_graph.py`

A LangGraph fan-out over the verified metrics:

```
START ─┬─ allocation_critic ───┐
       ├─ concentration_risk ──┤
       ├─ sip_health ──────────┼─→ synthesizer → END
       └─ performance_attribution ┘
```

Four parallel specialists each read a focused subset of the metric catalog and
write a short finding; the synthesizer weaves them into the narrative. There is
**no human-approval gate, no risk guardrail, no `interrupt_before` and no
checkpointer** — read-and-reason only. The graph carries no holdings: it reasons
over labels and precomputed displays.

It is invoked with **`portfolio_runnable_config()`** (F1), so LangSmith tracing
is off even under `LANGCHAIN_TRACING_V2=true`. `run_overview_graph` and
`overview_stream` both use it; a test asserts the invocation config carries no
live tracer.

## 4. LLM routing — `agents/llm.py`, `provider=` wins over env

`get_chat_llm(default_model, *, temperature=0, provider=None)`:

- `provider="openai"` → **real OpenAI**, base URL pinned to
  `https://api.openai.com/v1` even if `OPENAI_BASE_URL` is set (the underlying
  `openai` client reads that env var, so pinning is what makes the provider win).
  The portfolio agents pass this.
- `provider="groq"` / `"compat"` → Groq / an `OPENAI_BASE_URL` compat endpoint.
- `provider=None` (the Lab agents, **untouched**) → env default: compat **iff
  `OPENAI_BASE_URL` is set**, otherwise Groq.

**The v2 tightening:** a lone `OPENAI_COMPATIBLE_MODEL` no longer switches
provider. It is a v1 leftover (plan §9 says both vars stay unset in prod), and
requiring `OPENAI_BASE_URL` for compat mode means the stray var cannot reroute
the Lab off Groq or the portfolio graph onto a compat endpoint. Pinned by
`test_llm_routing.py`: portfolio → `ChatOpenAI`, Lab → `ChatGroq`, **even with
`OPENAI_COMPATIBLE_MODEL` set**.

Overview model: `OPENAI_OVERVIEW_MODEL` (default `gpt-4o-mini`).

## 5. Agents may not invent figures — `narrative.py`

The narrative is a list of paragraphs, each a list of **segments** — literal
prose or a metric reference:

```json
{"segments": [
  {"text": "the largest position is "},
  {"metric": "top_holding_weight", "display": "21.7%", "label": "…"},
  {"text": " of value."}
]}
```

The LLM writes prose and marks each figure with a `[[metric_key]]` token, never a
numeral. `parse_prose` substitutes the **Python-computed** `display` for each
token, so a number can only originate in `metrics.py`. `invented_figures()`
closes the loop: it renders the narrative to plain text and asserts every figure
traces to a metric display. If a model ever slips a bare numeral past the token
rule, the synthesizer node **falls back to the deterministic scripted prose**
(`scripted_overview_prose`, tokens only) — so the invariant holds unconditionally
at the route boundary.

## 6. Graceful degradation (hard requirement)

Metrics are always computed and always returned. Only the narrative needs the
model. The route degrades — never errors — when the model is unavailable:

- **no `OPENAI_API_KEY`** → preflight degrade, no spend;
- **over the spend ceiling** (§7) → degrade;
- **provider down / rate-limited mid-run** → the graph raises `OverviewLLMError`,
  the spend reservation is refunded, and the stream completes degraded.

A degraded `complete` event carries `degraded: true`, a `reason`
(`llm_unavailable` | `spend_cap` | `error`), an empty `narrative`, and the full
`metrics`. The panel shows "AI overview unavailable" while every number renders.
Pinned by `test_overview_api.py::test_overview_degrades_when_llm_key_is_removed`.

## 7. Spend controls — `agents/portfolio/spend.py`

An in-code, configurable **global daily ceiling** (`OVERVIEW_DAILY_GLOBAL_MAX`,
default 500) and a low **per-user daily cap** (`OVERVIEW_DAILY_USER_MAX`, default
20). Both **fail toward the degraded state, not an error**. State is in-memory
per-process (consistent with the rest of the Lab/overview state) and resets on
the UTC day. This is the cheap always-on guard; the hard stop is a provider-side
budget cap on the OpenAI dashboard (operator task — `docs/MORNING.md`).

## 8. Descriptive only (§8.3)

The system prompt forbids predictions, forecasts, targets, and any buy/sell/hold
call on a real holding. The overview describes what **is** — allocation,
concentration, realized return, SIP roster — nothing forward-looking.

## 9. SSE — `POST /portfolio/overview`

Same identity and source-error contract as the rest of `/portfolio/*`
(`portfolio_identity`: a verified Clerk JWT, or the interim admin secret until
L1; per-user connector). Metrics are computed first; a **source** failure
(unlinked → 409, throttled → 429, unreachable → 502) is returned as a typed HTTP
error **before** the stream opens, exactly as the dashboard already handles.
Then the stream:

- `start` — `{status, agents[]}`;
- `update` — one per specialist/synthesizer as it completes;
- `complete` — `{status, degraded, reason, narrative[], scripted, metrics[], agents[]}`.

Holdings for the metric computation are fetched per non-empty snapshot bucket
(the `UNKNOWN`/wallet bucket included, best-effort — IND Money refuses it and it
is simply skipped, matching the dashboard's holding count).

## 10. Demo artifact — `backend/tests/fixtures/demo/overview.json`

U1 serves the overview at `/demo` **statically** — never an LLM call at request
time — so the metric dict and narrative are frozen into `overview.json`. It is
generated by `agents/portfolio/demo.py`, which runs the real metric computation
over the StubConnector's invented portfolio and renders the **deterministic
scripted narrative** (no LLM, byte-reproducible in CI). Values are synthetic
(stub-derived) and safe to commit.

**Regenerate (manual step whenever the demo fixtures or scripted prose change):**

```bash
cd backend && python -m agents.portfolio.demo
```

`test_overview_api.py::test_demo_artifact_exists_and_matches_stub_fixtures`
recomputes the metrics from the fixtures and asserts the committed displays
match, so drift fails CI.

## 11. Frontend — `components/portfolio/AiOverview.tsx`

The panel per `docs/design/a2-overview.html`: narrative with inline blue metric
chips (each chip's figure is the computed `display`), agent fan-out chips
(running/done), the computed-metrics rail listing every available metric, and the
degraded state ("AI overview unavailable — every number still renders") as a
first-class part of the component. It consumes the SSE stream (`streamOverview`
in `lib/api.ts`) and renders fully from computed metrics whether or not the
narrative arrives. Mounted on `/portfolio` after the stat cards; it streams and
degrades independently and never blocks the rest of the dashboard.

## 12. What A1 deliberately does not do

- **No schema, no migration.** Metrics are computed on the fly from the live
  source; `alembic` is unaffected.
- **No XIRR, no forward projection, no instrument-level advice.**
- **No new runtime dependency.** `langchain-openai` was already pinned (v1's
  compat path); the graph uses the existing `langgraph`.
- **No provider-side budget cap.** That is an operator dashboard task
  (`docs/MORNING.md`); the app-side ceilings degrade long before it.
