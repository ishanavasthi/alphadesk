# F1 — how to run and verify the persistence layer

Everything below runs on a laptop with Docker. No Postgres is provisioned yet
(ruling R3), and **nothing in F1 assumes Neon** — any Postgres URL works.

## 0. One-time setup

```bash
source .venv/bin/activate                       # repo-root venv
pip install -r requirements.txt -r requirements-dev.txt
```

## 1. Start a local Postgres

```bash
docker run --rm -d --name alphadesk-f1-pg \
  -e POSTGRES_PASSWORD=test -e POSTGRES_DB=alphadesk \
  -p 5433:5432 postgres:16
```

Port **5433**, not 5432, so it cannot collide with a Postgres you already run.
Stop it when you are done:

```bash
docker stop alphadesk-f1-pg
```

## 2. Run the migration

```bash
cd backend
DATABASE_URL="postgresql+asyncpg://postgres:test@localhost:5433/alphadesk" \
  alembic upgrade head
```

`postgres://` and `postgresql://` work too — `alembic/env.py` normalises the
scheme to asyncpg. If `backend/.env` already has `DATABASE_URL`, `env.py` picks
it up and the prefix is unnecessary.

Expected, first run:

```
INFO  [alembic.runtime.migration] Context impl PostgresqlImpl.
INFO  [alembic.runtime.migration] Will assume transactional DDL.
INFO  [alembic.runtime.migration] Running upgrade  -> 0001, initial identity tables
```

Run it a second time — it must be a **no-op** (no `Running upgrade` line):

```
INFO  [alembic.runtime.migration] Context impl PostgresqlImpl.
INFO  [alembic.runtime.migration] Will assume transactional DDL.
```

Confirm the schema and the cascades:

```bash
docker exec alphadesk-f1-pg psql -U postgres -d alphadesk -c "\dt"
docker exec alphadesk-f1-pg psql -U postgres -d alphadesk \
  -c "SELECT conname, confdeltype FROM pg_constraint WHERE contype='f';"
```

`confdeltype = c` is `ON DELETE CASCADE`. Both FKs must show `c`.

Check the migration has not drifted from the models:

```bash
DATABASE_URL="postgresql://postgres:test@localhost:5433/alphadesk" alembic check
# -> No new upgrade operations detected.
```

## 3. Run the tests

```bash
cd backend
pytest
```

Expected: **22 passed**.

### Which database the tests use

`tests/conftest.py` takes `TEST_DATABASE_URL`, else `DATABASE_URL`, else the
default `postgresql+asyncpg://postgres:test@localhost:5433/alphadesk`, and then
**works on a separate `<db>_test` database on the same server** — with the
container above, `alphadesk_test`. It is dropped and recreated at the start of
the session, so a dev database is never touched and a run never inherits state.

Its schema is built by running **`alembic upgrade head`** programmatically (via
`config.attributes["db_url"]`), so the tests exercise the migration operators
that production will run, not a parallel `SQLModel.metadata.create_all()` that
merely happens to agree today. Each test truncates the three tables afterwards.

**No Postgres reachable?** The six DB tests skip with a message naming the URL
they tried, and the other 16 still run:

```
tests/test_db_identity.py ssssss
SKIPPED [1] tests/test_db_identity.py:30: No Postgres reachable at
postgresql+asyncpg://postgres:test@localhost:5599/postgres (OSError). Start it
with the docker one-liner in docs/TESTING/F1.md, or set TEST_DATABASE_URL.
======================== 16 passed, 6 skipped in 0.11s =========================
```

That keeps `pytest` green on a Docker-less machine **without hiding anything** —
a skip says exactly what was not proven. Do not accept skips as verification
when reviewing F1 work: the DB tests must have run.

## 4. What each test proves

### `tests/test_crypto.py` (9)

| Test | Proves |
| --- | --- |
| `test_round_trip_is_identity` | `decrypt(encrypt(x)) == x` |
| `test_ciphertext_does_not_contain_plaintext` | the token differs from the plaintext, and no 8-character run of the secret survives in it |
| `test_encryption_is_non_deterministic` | random IV per call — the same token stored twice does not produce matching rows |
| `test_round_trip_survives_unicode_and_empty_strings` | empty, whitespace, Devanagari, 4 KB values |
| `test_missing_key_raises_a_clear_error` | missing `TOKEN_ENCRYPTION_KEY` fails loudly, naming the var and the generate-a-key command |
| `test_invalid_key_raises_without_echoing_the_key` | a bad key does not end up in the error message (and so not in a log) |
| `test_decrypt_with_a_different_key_fails_loudly` | key rotation cannot silently return garbage; the ciphertext is not echoed |
| `test_tampered_ciphertext_is_rejected` | Fernet's authentication actually fires |
| `test_optional_helpers_pass_none_through` | nullable `*_enc` columns |

### `tests/test_db_identity.py` (6, needs Postgres)

| Test | Proves |
| --- | --- |
| `test_migration_created_the_three_tables` | the migration produced `users`, `broker_links`, `oauth_pending` — **and nothing else** beyond `alembic_version` (no speculative portfolio tables) |
| `test_broker_link_round_trip_stores_only_ciphertext` | the card's headline guarantee. Writes a link with three encrypted fields, then reads the **raw** columns with SQL (bypassing the ORM) and asserts each differs from the plaintext, does not contain it, and decrypts back to it — then serialises the whole row to text and asserts no secret appears anywhere in it |
| `test_one_link_per_user_and_source` | `UNIQUE (user_id, source)` — re-linking cannot create a duplicate |
| `test_deleting_a_user_cascades_to_links_and_pending` | a raw `DELETE FROM users` removes that user's `broker_links` **and** `oauth_pending` rows and leaves another user's rows alone. Raw SQL on purpose: an ORM delete would pass even if the cascade were only an ORM relationship |
| `test_link_requires_an_existing_user` | the FK rejects an orphan link |
| `test_timestamps_are_timezone_aware` | `timestamptz`, not naive `timestamp` — S1's 06:00-IST day cutoff depends on it |

### `tests/test_portfolio_config.py` (7)

All seven run with `LANGCHAIN_TRACING_V2=true`, `LANGSMITH_TRACING=true` and an
API key exported — the exact situation the helper exists for. Assertions are on
the resolved callback manager and on a call log; **no network is involved.**

| Test | Proves |
| --- | --- |
| `test_the_env_var_really_would_enable_tracing` | **the control case.** With no config, a live `LangChainTracer` *is* attached — without this, the rest of the file would pass trivially |
| `test_empty_callbacks_are_not_enough` | `callbacks=[]` and `callbacks=None` still resolve to a live tracer — documents why the helper is not one line |
| `test_portfolio_config_resolves_to_no_live_tracer` | `portfolio_runnable_config()` resolves to zero LangSmith-writing tracers |
| `test_invoking_a_runnable_with_the_config_writes_nothing` | actually invokes a two-step chain: the null client records **zero** calls, and the *nested* runnable sees only `TracingDisabledTracer` — i.e. children inherit the switch |
| `test_tags_and_configurable_are_carried_through` | `thread_id`, `run_name`, tags, metadata, `configurable`, `recursion_limit` survive, and tracing is still off (metadata triggers langchain's handler-copy path, which is where a naive implementation breaks) |
| `test_helper_does_not_disable_tracing_globally` | the switch is scoped to the config — the research pipeline keeps tracing |
| `test_inert_tracer_ignores_every_callback_category` | all seven `ignore_*` flags are set, so the manager dispatches nothing to it |

## 5. Verify the tracing switch inside the Docker image

`requirements.txt` pins direct deps only, so the image resolves **langchain-core
transitively** and can carry a different version than the dev venv (1.5.5 in the
image vs 1.4.9 in the venv when F1 shipped). The kill switch rides on a
langchain-core internal, so check it where it will actually run:

```bash
docker build -t alphadesk-f1 .
docker run --rm -e LANGCHAIN_TRACING_V2=true -e LANGCHAIN_API_KEY=dummy \
  -w /app/backend alphadesk-f1 python -m tests.check_tracing_in_image
```

Expected (exit 0):

```
langchain-core 1.5.5
baseline (no config)        : ['LangChainTracer']
portfolio_runnable_config() : ['TracingDisabledTracer']
invoke result               : 7
langsmith client calls      : []
OK: portfolio_runnable_config() suppresses tracing in this image
```

The script needs no pytest, which is why it lives beside the tests rather than
in them. **Re-run it after any langchain, langsmith or langgraph bump.**

## 6. Image still builds and boots

```bash
docker build -t alphadesk-f1 .            # ~12s, no apt layer
docker images alphadesk-f1 --format "{{.Size}}"     # 426MB (was 370MB pre-F1)
docker run --rm -d --name alphadesk-f1-boot -p 7861:7860 alphadesk-f1
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:7861/docs   # 200
docker stop alphadesk-f1-boot
```

Alembic is in the runtime image too, so production can migrate itself:

```bash
docker run --rm -w /app/backend -e DATABASE_URL="postgresql+asyncpg://u:p@h/d" \
  alphadesk-f1 alembic upgrade head --sql        # prints the DDL, needs no DB
```
