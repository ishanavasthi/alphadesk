# B8 — how to run and verify top movers (backend)

Everything below runs on a laptop with Docker. Spec: `docs/SPECS/B8.md`.

## 0. Local Postgres

The DB tests need a real Postgres — the container from `docs/TESTING/F1.md`:

```bash
docker run --rm -d --name b8-pg \
  -e POSTGRES_PASSWORD=test -e POSTGRES_DB=alphadesk \
  -p 5433:5432 postgres:16
```

Without it the DB-backed tests **skip loudly** rather than failing. **Never
point the suite at Neon** — the conftest guard (`resolve_test_database_url`)
refuses a non-loopback `DATABASE_URL`, because the fixture runs
`DROP DATABASE … WITH (FORCE)`. Tear down with `docker rm -f b8-pg`.

## 1. Migration

```bash
cd backend
DATABASE_URL="postgresql+asyncpg://postgres:test@localhost:5433/alphadesk" \
  alembic upgrade head
```

Expected tail on a fresh database:

```
INFO  [alembic.runtime.migration] Running upgrade 0005 -> 0006, portfolio read-through cache
INFO  [alembic.runtime.migration] Running upgrade 0006 -> 0007, snapshot_holdings.name …
```

Run it again — it must be a **no-op** (no `Running upgrade` line). Then:

```bash
DATABASE_URL="…/alphadesk" alembic heads   # -> 0007 (head)      one head, not two
DATABASE_URL="…/alphadesk" alembic check   # -> No new upgrade operations detected.

docker exec b8-pg psql -U postgres -d alphadesk -c '\d snapshot_holdings' | grep name
#  name | text |  |  |            nullable, and it stays nullable
```

`downgrade -1` drops the column cleanly.

## 2. Backend tests

```bash
cd backend && pytest
```

**729 passed, 1 skipped** on the B8 tip (715 before + 14 new in
`tests/test_movers.py`). The one skip is `test_overview_live.py`, which is
opt-in behind `RUN_OPENAI_LIVE=1` and unrelated to this card — **no DB test may
skip**; if they do, the container in §0 is not running.

## 3. The claims, and the test that pins each

Every row below is a sentence about someone's money.

| Claim | Test |
|---|---|
| a holding whose **value** doubles while its **price** falls 10% is a *loser* — `change_pct` comes from the price, never the value | `test_price_basis_ranks_on_price_not_value` |
| an unpriced balance (SA/FD/cash) lands in `flows` with `change_pct: null`, and never in `gainers`/`losers` — even when it is the window's largest ₹ move | `test_balance_rows_are_flows_never_movers` |
| a position present on one day only is `opened`/`closed` with **both** `change_abs` and `change_pct` null — never ±100% (incl. the honestly-empty `{"rows": []}` bucket) | `test_opened_and_closed_are_never_plus_or_minus_100` |
| an asset type in `buckets_failed` on **either** compared day is excluded from every list and named in `excluded` — a throttled bucket never reads as "sold" | `test_failed_bucket_is_unknown_not_empty` |
| the window snaps **inwards** to captured days and `note` names the two actually compared; an exact hit has `note: null` | `test_window_snaps_to_captured_days_and_says_so` |
| one captured day in the window → empty lists + a note, never a widened window | `test_single_captured_day_in_window_is_empty_with_a_note` |
| the join is on `(source, external_id)`, so two NULL-`symbol` MF rows stay two holdings | `test_join_is_on_identity_pair_not_symbol` |
| `name` comes from the column; pre-B8 rows fall back to `snapshot_raw`; a pruned row stays `null` rather than being guessed | `test_name_comes_from_the_column_and_falls_back_to_raw` |
| `limit` caps each of gainers and losers independently | `test_limit_caps_each_side_independently` |
| no snapshots at all → an empty report with a note, not an error | `test_no_snapshots_at_all_is_an_empty_report` |
| **capture actually fills the new column** (the migration is useless otherwise) | `test_capture_stores_the_display_name` |
| `GET /portfolio/movers` with no identity → **401**, never a fall-through | `test_movers_requires_an_identity` |
| the contract shape: `requested`/`compared`/`note`/five lists/`excluded`, exact entry keys, every money field a **string** | `test_movers_returns_the_contract_shape` |
| no `DATABASE_URL` → **200** with empty lists and a note, never a 500 | `test_movers_without_a_database_is_200_with_a_note` |

The service tests build days and holdings by hand against the **real migrated
database** — every rule this card exists for is a rule about which rows end up
in which list, and a hand-built pair of days is the only way to state one case
per test. The route tests drive the ASGI app, because the identity gate and the
no-database degradation are part of the contract the frontend codes against and
neither is visible from the service.

## 4. Manual check against real captured data

Single-tenant dev, with at least two captured days:

```bash
cd backend && ALPHADESK_SINGLE_TENANT=1 uvicorn api.main:app --reload --port 8000
curl -s 'localhost:8000/portfolio/movers?limit=5' | python -m json.tool
```

What to look at, in order:

1. `compared` — the two days actually compared, and `note` if they differ from
   what you asked for.
2. `gainers[0].change_pct` against `start_price`/`end_price` by hand. It must
   reconcile with the **prices**; if it reconciles with the values instead,
   something regressed.
3. `flows` — savings accounts and deposits belong here and nowhere else.
4. `excluded` — non-empty means a bucket failed on one of those two days, and
   its rows are correctly missing from every list rather than reported as sold.
