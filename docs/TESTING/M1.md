# M1 — how to verify the portfolio model and connectors

Companion to [`docs/SPECS/M1.md`](../SPECS/M1.md). Everything below runs offline
except the live smoke test in §4.

```bash
source .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
cd backend
pytest                      # 371 passed, 6 skipped without a Postgres
```

The 6 skips are F1's DB tests; they skip loudly, naming the URL they tried. No
Postgres, no network and no IND Money credential is needed for any M1 test.

---

## 1. The five test files, and what each one actually proves

### `tests/test_portfolio_models.py` — 50 tests

The rules the *types* enforce, so a future connector cannot opt out of them by
forgetting. Grouped by the C2 finding each defends:

| Group | Proves |
| --- | --- |
| Decimal coercion | `to_decimal(0.1) == Decimal("0.1")` (i.e. it goes through `str`, not binary float); `int` and `float` inputs for the same field land identically; bools and junk raise; **NaN/±Infinity raise** (they parse happily and then poison every sum); **formatted numbers raise** (`"1,234.56"` is a display string, and guessing at it moves a value three orders of magnitude). |
| Cost basis | `invested_amount=0` is **rejected outright** by `Holding` and `AllocationSlice`; a `None` basis cannot carry a P&L; a *known* basis may carry a legitimate `0` return; `derive_pnl` refuses `None`/`0` and returns a real −100% for a worthless holding. |
| `as_of` | Naive datetimes raise; aware ones normalize to UTC. |
| Currency | Any non-INR value raises — **including the empty string, deliberately** ("no currency stated" is not evidence of INR); `"inr"` normalizes; all five models default to INR; US exposure is signalled by `asset_type` alone, including for the out-of-enum wallet bucket. |
| Asset types | `queryable()` is exactly the vendor's 16; six kinds of junk all coerce to `UNKNOWN` without raising; the original string survives. |
| Absences | No model has an `xirr` field; unknown fields are rejected; the enums match the documented vocabularies. |

The `stable_external_id` test is worth naming: it caught a real ambiguity bug —
the first implementation joined parts with a separator, so `("a|b",)` and
`("a","b")` hashed identically. It now JSON-encodes first.

### `tests/test_portfolio_ind_money_connector.py` — 82 tests

The vendor mapping, driven entirely off the **C2 synthetic fixtures** through an
injected transport (`tests/ind_money_transport.py`). No network, no credential.
Highlights:

- **Transport contract** — the connector consumes exactly what
  `tools.ind_money._unwrap` produces, proven by feeding it the committed
  `raw_mcp_envelope__*.json` through the real `_unwrap`.
- **Snapshot** — totals are passed through byte-for-byte (`Decimal(str(...))` of
  the payload value), the un-enumerable `US_STOCK_WALLET` bucket survives as
  `UNKNOWN` with its string intact and is recognised as US exposure, a missing
  total is a typed error, and an empty portfolio is not an error.
- **Holdings** — all six MF fixture rows map; the three unknown-cost-basis
  encodings (key absent, `0`, `null`) all yield `None` basis **and** `None` P&L;
  the zero-*value* row keeps its real −100%; the all-`int` row still yields
  `Decimal`; a cash-like row's `0` units/price become `None` rather than reading
  as a real price; empty asset types return `[]`; ids are unique and an empty
  instrument code falls back to a stable hash; empty display names become
  `None`; a `US_STOCK` row is flagged by asset type alone.
- **The UNVERIFIED `IND_STOCK` boundary** — the empty 19-key envelope maps to no
  rows; a documented-shape row maps; an **unexpected key** and a **missing
  value** each raise `UnverifiedShapeError`; and the same unexpected key on an
  `MF` row does **not** raise (forward-compatibility is deliberate everywhere
  except behind the unverified boundary).
- **Rate limiting** — a throttled response is retried after the server's own
  `retry_after_seconds` (recorded, not slept); the backoff is capped; both tiers
  raise `RateLimited` carrying `scope`/`window`/`limit`/`current`/`cost`; and a
  parametrized test proves a throttled body **never reaches the payload parser**
  on any of the four entry points. A non-rate-limit `error` body is a
  `SourceReportedError`; a missing key is a `PayloadShapeError`, never a
  `KeyError`.
- **Currency** — a doctored payload with `"currency": "USD"` raises
  `NonInrValue`; so does a nested one (and the error names the JSON path); an
  `"INR"` one passes. The doctoring happens **in the test**, deliberately not as
  a committed fixture: `test_ind_money_fixtures.py` asserts no committed fixture
  contains a currency key, and that assertion is correct and must stay.
- **Scoping and health** — every method refuses a `user_id` the connector is not
  bound to *before any network call*; all four `link_health` states are covered,
  including that a definitive rejection is `revoked` (and sticky) while a
  transient failure is only `needs_relink`.
- **Nothing escapes untyped** (fix round 1) — a dead credential surfaces as
  `NotLinked` (and marks the link revoked), a client-library error and any
  arbitrary exception as `SourceUnavailable`, and both are catchable as
  `PortfolioSourceError`. Malformed money values (`"1,234.56"`, `NaN`,
  `Infinity`, `{}`, `[]`) raise `PayloadShapeError` naming the **JSON path**,
  on both the row and the aggregate paths.
- **Failure is never rendered as emptiness** (fix round 1) — a truthy
  `holding_error` / `position_error` raises even though `holdings` is `[]`,
  while both flags being `false` is the ordinary empty case.
- **Identity does not merge two positions** (fix round 1) — two code-less,
  name-less, broker-less rows with genuinely different values get different
  ids; the fallback is deterministic for a given response; and a *coded* row
  keeps the same id regardless of its position, so the fallback's
  position-dependence does not leak into the common path.
- **The source's own P&L wins** (fix round 1) — a row whose `total_pnl` /
  `pnl_per` deliberately disagree with `current_value − invested_amount` is
  passed through, not recomputed; a *partial* pair falls back to deriving both.
- **Aggregate slices degrade like rows** (fix round 1) — a bucket or breakdown
  slice with `invested_value: 0` yields `None` cost basis and `None` P&L rather
  than a bare `ValidationError`.
- **Throttling details** (fix round 1) — a throttle body with no
  `retry_after_seconds` still waits (floored, not instant); a falsy `error`
  value (`false`, `""`, `0`, `None`) is not treated as a failure.
- **Strictness behind the boundary** (fix round 1) — an `IND_STOCK` row missing
  *any* documented key raises, while the legitimately-absent `invested_amount`
  is still tolerated.
- **The reconciliation gap** — the holdings sum differs from both snapshot
  totals on this source's fixtures. This lives here, not in the contract suite:
  it is a property of the data, not of the interface.

### `tests/test_portfolio_connector_contract.py` — 48 tests

**One suite, parametrized over both connectors.** This is the file that makes
the seam real; a future source joins by adding one line to `CONNECTORS`.

It proves: both implement every abstract method, async, with `user_id` as the
first argument; both return typed, INR-denominated, UTC-stamped objects; both
have a non-empty portfolio with unique identities; both carry an
unknown-cost-basis row that yields `None` P&L; both treat an empty allocation
combination as a valid answer; and both refuse an empty `user_id`.

**Out-of-enum behaviour is asserted per connector, from a declared map**
(`UNKNOWN_ASSET_TYPE_BEHAVIOUR`): the stub *enumerates* its `US_STOCK_WALLET`
bucket, IND Money *refuses* both `fetch_holdings` and `fetch_allocation`. An
earlier version swallowed `UnsupportedAssetType` and returned early, which let
IND Money silently skip every assertion the stub had to pass — a contract test
one implementation can opt out of is not a contract test. A third test asserts
every connector declares which way it goes, and that the map is not degenerate.

`all_holdings()` carries a pacing warning in its docstring: sixteen calls to one
tool is exactly the single-tool burst that trips the 15/min per-tool limit
first. It is safe here only because both connectors are offline.

### `tests/test_portfolio_stub_connector.py` — 18 tests

The stub's own behaviour, which the shared contract cannot see:

- **per-user portfolios** — two users get two genuinely different portfolios
  (holdings *and* snapshot), an unmapped user falls back to the public demo.
  This is F4's isolation seam; if the stub served one portfolio to everybody,
  an isolation test against it could never fail;
- **injected `link_health`** — every one of the four states, which is how a UI
  or isolation test rehearses expiring / needs-relink / revoked without a
  credential;
- **no shared mutable state** — the loader returns a fresh document (asserted
  down to the nested containers, because the model copies the top-level `raw`
  dict and would mask a cache at that level), and a caller scribbling on what it
  was handed cannot corrupt the next load;
- the demo portfolio still carries every edge case its README claims, and its
  holdings sum still differs from its snapshot total.

### `tests/test_portfolio_boundary.py` — 62 tests

Two greps over `backend/portfolio/` (excluding `connectors/`):

- an **AST code-token** grep that sees identifiers and live string literals but
  not docstrings or comments — the load-bearing one. It covers vendor names
  that are also ordinary English (`investment`, `broker`) without tripping on
  prose, and it is what catches payload parsing in the wrong file;
- a **whole-file** substring grep for the unambiguous names, which additionally
  catches a leak hiding in a comment.

Plus: the model layer imports neither `tools.ind_money` nor any connector; a
**non-vacuity** test asserting those same names *do* appear below the boundary
(a grep test that could never fail is worse than no test); and a test proving
the two greps genuinely differ on prose.

The throttle-body keys (`rate_limit_exceeded`, `retry_after_seconds`) are in the
banned set because a review found `RateLimited.from_body()` parsing a vendor
body inside `errors.py` while the grep of the day passed. Re-introducing that
parsing now fails
`test_no_vendor_name_is_used_in_code_above_the_boundary[retry_after_seconds]`.

## 3. Fixture pinning — read before editing any fixture

**The connector tests deliberately assert exact row counts and exact values
from the C2 fixtures**: "6 MF rows", "3 rows with an unknown cost basis", "the
worthless row's `pnl_pct` is −100.0", "13 sector rows in the snapshot". These
are not incidental — each one is guarding a specific edge case
`backend/tests/fixtures/ind_money/README.md` says that fixture exists to
exercise. A test that said "some rows" would pass just as happily against a
fixture someone had tidied.

The consequence: **the fixtures and these assertions are one artifact and must
be updated together.** If a future card re-synthesizes
`backend/tests/fixtures/ind_money/` (the highest-value reason being a capture
from an account that actually holds Indian stocks — see the C2 README's
regeneration policy), it must also re-derive:

- the counts in `test_portfolio_ind_money_connector.py`;
- `HOLDINGS_FIXTURES` / `BREAKDOWN_FIXTURES` in `tests/ind_money_transport.py`;
- the edge-case guards in `test_ind_money_fixtures.py` (C2's own).

The same applies to `backend/tests/fixtures/demo/` and
`test_portfolio_stub_connector.py`. Its README lists seven edge cases the demo
portfolio deliberately contains; the stub tests assert each is still there, so
removing one fails a test rather than silently weakening the suite.

Tests that are deliberately **not** pinned, and must stay that way: nothing
asserts on `type()` of a money value (the API emits `int` and `float` for the
same field), and nothing asserts a holdings sum *equals* a snapshot total.

### Mutation probes — how these tests were checked

The suite being green proves nothing on its own; what matters is whether it goes
red when the behaviour changes. Every degrade rule and every fix in round 1 was
verified by **applying the mutation and confirming a named test fails**:

| Mutation | Caught by |
| --- | --- |
| vendor P&L pass-through → always `derive_pnl` | `test_the_sources_own_pnl_is_passed_through_not_recomputed` |
| allocation `invested_value == 0 → None` removed | `test_a_zero_invested_bucket_degrades_instead_of_raising` |
| stub ignores its per-user `portfolios` map | `test_two_users_get_two_genuinely_different_portfolios` |
| stub `link_health` hard-codes `LINKED` | `test_the_injected_link_health_is_honoured[expiring]` |
| stub caches its demo files (shared dicts) | `test_the_loader_returns_a_fresh_document_every_time` |
| `fetch_allocation`'s UNKNOWN guard removed | `test_an_out_of_enum_allocation_behaves_as_documented[ind_money-assets]` |
| vendor body parsing back in `errors.py` | `test_no_vendor_name_is_used_in_code_above_the_boundary[retry_after_seconds]` |
| transport failures left unwrapped | `test_a_dead_credential_surfaces_as_not_linked` |
| broker-side fetch-failure flags ignored | `test_a_broker_side_fetch_failure_is_not_an_empty_portfolio[holding_error]` |
| id fallback drops its disambiguator | `test_the_id_fallback_does_not_merge_two_indistinguishable_rows` |
| money-value errors untyped again | `test_a_malformed_money_value_is_typed_and_says_where[1,234.56]` |
| backoff floor removed | `test_a_throttle_without_a_delay_still_waits` |
| falsy `error` treated as a failure | `test_a_falsy_error_key_is_not_an_error[False]` |
| strict mode only requires `market_value` | `test_strict_mode_requires_the_whole_documented_key_set` |

One probe earned its keep immediately: the first version of the shared-state
test asserted `first.raw is not second.raw`, which **passed under the cache
mutation** because pydantic copies a top-level `dict` field. The test now
asserts on the loader and on the nested containers, and the mutation dies.

## 4. The leak gate

The repo is public and the demo fixtures are invented, so the C2 adversarial
check still applies to anything M1 adds under `docs/` or `backend/tests/`.

```bash
cd backend
python tests/leak_check_ind_money.py --captures <scratch-dir> --self-test
python tests/leak_check_ind_money.py --captures <scratch-dir>
```

`--self-test` plants a real capture value in a temp file outside the repo and
requires the scanner to catch it, so a PASS on the real files cannot be vacuous.
The scan itself needs a capture corpus, which C2 deleted after its gate — see
`docs/TESTING/C2.md` for how to re-capture into a scratch directory **outside**
the working tree, and delete it afterwards.

**Result on this branch (2026-08-15), run twice.**

- *First pass, before review fixes.* `--self-test` PASS; the real scan over 47
  files **FAILED with 6 string overlaps** — invented fund and sector labels that
  happened to share an ordinary English word with the operator's real payload.
  No amount, id or holding was involved. The labels were rewritten to C2's
  neutral convention (`Demo Sector Alpha/Beta/…`) and the gate re-run: **PASS**.
- *Second pass, after fix round 1.* **FAILED with 6 more overlaps**, of two
  kinds: a round SIP amount in the demo fixtures and its matching test
  assertion, which collided with a real number; and — instructively — a line in
  **this document** that had *named* the words involved in the first failure.
  Naming them republished the fact that the operator's portfolio contains those
  sectors, which is exactly the kind of disclosure the gate exists to stop. The
  amount was changed and this paragraph was rewritten to describe the collisions
  without reproducing them. Gate re-run: **PASS** over 49 files.

Both times, the captures were deleted immediately afterwards.

The lesson worth carrying: **a gate finding is not a formality to be documented
away.** Writing "the colliding word was X" leaks X. Describe the shape of the
problem, never its content — and re-run the gate after editing the docs, not
just after editing the fixtures.

It is also why the demo fixtures avoid plausible real-world sector names and
round-number amounts entirely.

## 5. Live smoke test

Optional, and the only thing here that touches the network. It proves the
connector maps a **real** payload, not just the fixtures.

Constraints, all of them deliberate:

- Run it from the **main checkout's** `backend/`, so the real `.env` and the
  real `backend/.ind_money_token.json` are the ones used, with the M1 worktree's
  `backend/` appended to `sys.path` so `portfolio.*` resolves to this branch.
- **Report only counts, types and conformance booleans. Never a value.** The
  repo is public; a portfolio total in a doc or a commit is the one failure this
  whole card is built to avoid.
- Pace it: 4 seconds between calls, 3 calls total. The per-tool limit is 15/min
  and the global one 30/min, so this is nowhere near either. Do **not** loop
  over all 16 asset types, and never sweep the 48-call allocation grid.

Sketch (the version used for this card lived in a scratch dir, not the repo):

```python
sys.path.insert(0, "<main>/backend")     # tools.* + the token cache beside them
sys.path.append("<worktree>/backend")    # portfolio.* from this branch
load_dotenv("<main>/backend/.env")

connector = IndMoneyConnector(transport=...)   # wraps tools.ind_money._call_mcp_tool
print(await connector.link_health("local"))
snapshot = await connector.fetch_snapshot("local")
for asset_type in (AssetType.MF, AssetType.IND_STOCK):
    await asyncio.sleep(4)
    rows = await connector.fetch_holdings("local", asset_type)
    # print len(rows), types, and booleans — nothing else
```

**Result on this branch (2026-08-15), against the operator's live account:**

| Check | Result |
| --- | --- |
| `link_health` | `linked` (token auto-refreshed, no re-auth needed) |
| `fetch_snapshot` | returned a `PortfolioSnapshot`; `net_worth` is a `Decimal` and > 0; gross / invested / liabilities all present |
| snapshot `currency` / `as_of` | `INR` / tz-aware UTC (stamped, since no payload carries a date) |
| snapshot breakdown rows | 4 asset-type, 3 asset-class, 13 sector, 4 market-cap |
| asset types seen | `MF`, `SA`, `US_STOCK`, `UNKNOWN` |
| raw asset-type strings | `MF`, `SA`, `US_STOCK`, **`US_STOCK_WALLET`** — the out-of-enum bucket mapped to `UNKNOWN` with its string intact, exactly as C2 predicted |
| US-exposure buckets | 2 |
| `fetch_holdings(MF)` | 9 rows, all typed `Holding`, all INR, all tz-aware, all values `Decimal`, 9 unique ids, 9 with a `pnl_pct`, 0 with an unknown cost basis |
| `fetch_holdings(IND_STOCK)` | 0 rows — the 19-key envelope parsed cleanly and the account still holds no Indian stocks |
| conformance | no exception, no shape error, no currency error |

Two things this did **not** verify, and cannot until the account changes: a
populated `IND_STOCK` row, and a real unknown-cost-basis row (this account is on
IND Money's own rails, so `invested_amount` was present on all 9 MF rows — the
0/`null`/absent paths are covered by fixtures only).

The raw payloads were written to a scratch directory outside the repo purely so
the leak gate in §4 could be run against this branch, and **deleted immediately
afterwards**.

## 6. Scope check

```bash
git diff main --name-only
```

Must list only `backend/portfolio/**`, `backend/tests/**` and `docs/**`. Any
hit under `backend/api/`, `backend/agents/`, `backend/graph/`, `backend/tools/`,
`backend/db/`, `Dockerfile` or `requirements*.txt` means the card exceeded its
scope.
