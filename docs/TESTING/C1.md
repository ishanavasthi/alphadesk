# C1 — how to verify

C1 changed no Python, so there is nothing to unit-test. What has to be proven
is that **the image still builds and the app still runs once chromadb and the
`data/` corpus are gone**. Four checks, all runnable by hand from a fresh
session. Run them from the repo root of a checkout of `chore/slim-image`.

Prereqs: Docker running; the repo-root venv at
`/Users/ishan/Desktop/code/alphadesk/.venv` (Python 3.12) for check 3.

---

## 1. The image builds clean, with no apt layer and no chromadb

```bash
docker build --progress=plain --no-cache -t alphadesk-c1 . 2>&1 | tee /tmp/build.log
grep -ic "chromadb"        /tmp/build.log   # expect 0
grep -ic "build-essential" /tmp/build.log   # expect 0
grep -ic "onnx"            /tmp/build.log   # expect 0
grep -ic "apt-get"         /tmp/build.log   # expect 0
docker images alphadesk-c1 --format '{{.Size}}'
```

**Proves:** the slimming actually landed — no compiler toolchain is installed,
no vector store is pulled, no embedding model is downloaded at build. If any
grep returns non-zero, something re-introduced the RAG stack.

**Observed (2026-08-15):** exit 0, all four greps `0`, image **370MB**, full
no-cache build ~15s. `pip install` resolved the ten pins into 60 packages —
`chromadb`, `pypdf`, `langchain_text_splitters` and `onnxruntime` absent from
the installed list.

## 2. The app imports and serves inside that image

```bash
docker run --rm -d -p 7861:7860 --name alphadesk-c1 alphadesk-c1
sleep 6
curl -s -o /dev/null -w "HTTP %{http_code}\n" http://localhost:7861/
curl -s -o /dev/null -w "HTTP %{http_code}\n" http://localhost:7861/docs
curl -s -w "\nHTTP %{http_code}\n" http://localhost:7861/auth/status
docker logs alphadesk-c1 | grep -i "error\|traceback\|ModuleNotFound"   # expect nothing
docker stop alphadesk-c1
```

**Proves:** `api.main:app` and everything it transitively imports — including
`rag.retriever`, which is imported by the Analyst — load with chromadb absent.
This is the check that would catch a hard `import chromadb` at module scope.
`/auth/status` returning `authenticated:false` is the expected clean state for
a fresh container (no token cache baked into the image — also confirms no
credentials leaked into the build).

**Observed (2026-08-15):** `/` → HTTP 200, `/docs` → HTTP 200,
`/auth/status` → HTTP 200 with
`{"authenticated":false,"source":null,"expires_at":null,"expires_in_sec":null}`.
Logs: `Application startup complete.` and three 200s, zero errors/tracebacks.

## 3. Host-side end-to-end pipeline run (Analyst works with empty RAG context)

Needs a connected IND Money session. From the repo root:

```bash
cp /Users/ishan/Desktop/code/alphadesk/backend/.env backend/.env
cp /Users/ishan/Desktop/code/alphadesk/backend/.ind_money_token.json backend/.ind_money_token.json
cd backend
/Users/ishan/Desktop/code/alphadesk/.venv/bin/python -m uvicorn api.main:app --port 8011 &
sleep 8
curl -s http://localhost:8011/auth/status          # need "authenticated":true
curl -N -X POST http://localhost:8011/analyze \
  -H 'Content-Type: application/json' \
  -d '{"query":"IT sector momentum"}'
```

Then kill the server and **delete `backend/.env` and
`backend/.ind_money_token.json`** — both are gitignored, but the repo is public;
never let them near a commit.

If `/auth/status` says `authenticated:false`, `/analyze` returns 409 by design.
That is an environment problem, not a C1 regression — fall back to checks 1, 2
and 4 and say so.

**Proves:** the full graph (scanner → research → analyst → risk_manager → human
gate) runs and the Analyst emits complete, structured reports while the RAG
retriever contributes nothing. `citations: []` on every recommendation is the
direct evidence that RAG context was empty.

**Observed (2026-08-15):** `authenticated:true` (source `oauth`). The SSE stream
delivered `start`, four `update` events (`scanner`, `research`, `analyst`,
`risk_manager`) and one `complete`.

Shape of the `complete` payload — **symbols, scores and ids below are
placeholders**; this repo is public, so real run output never goes in a doc:

```
status=awaiting_approval  awaiting_approval=true  rejection_reason=None
action_id=<uuid>
5 analyst_recommendations, 5 risk_assessments

SYM1 buy  0.78 citations=[]   PASS
SYM2 buy  0.76 citations=[]   PASS
SYM3 buy  0.75 citations=[]   PASS
SYM4 hold 0.72 citations=[]   FLAG
SYM5 hold 0.64 citations=[]   REJECT
```

Each recommendation carried a full payload (`thesis`, `bull_thesis`,
`bear_thesis`, `key_risks`, `catalysts`, `target_price`, `time_horizon`), and
the risk guardrails behaved as documented — below 0.70 → REJECT,
[0.70, 0.75) → FLAG, ≥ 0.75 → PASS. The run paused at the human gate as
expected; it was not approved.

**What to check when you re-run this**, rather than matching the numbers above:
five recommendations each with a non-empty `thesis` and **`citations: []`**; a
`decision` per symbol consistent with the confidence bands; `status` of
`awaiting_approval` with an `action_id` present. The symbols and scores will
differ every run — they depend on live market movers.

Caveat on interpretation: the host venv *does* still have chromadb installed,
so on the host the retriever opens the store and finds it empty, whereas in the
image the import itself fails. Both paths land in the same
`except → _init_failed → return []` branch, and check 2 is what covers the
import-missing path specifically.

## Regression watch

- If a future card adds a dependency, it must be **pinned** in
  `requirements.txt`. Re-run check 1 after any dependency edit — an unpinned
  dep is the exact failure mode that took prod down with `mcp` 2.0.0.
- If anyone reintroduces a binary file (screenshot, PDF, model), the HF Space
  push will start failing its binary policy again. Keep binaries out of git.
