### macOS caveat: `--window-size=375` does not give you a 375px layout

On macOS the platform window has a minimum width (~500px), so
`--headless --screenshot --window-size=375,900` lays the page out wider and then
**crops** the image to 375 — which looks exactly like horizontal overflow and
is not. Two ways round it:

```bash
# (a) render inside a 375px iframe and screenshot the harness
cat > frame375.html <<'EOF'
<!doctype html><meta charset="utf-8">
<style>body{margin:0;background:#d4d4d8}
iframe{width:375px;height:2700px;border:0;display:block;background:#fff}</style>
<iframe src="http://127.0.0.1:3010/portfolio"></iframe>
EOF
"$CHROME" --headless=new --disable-gpu --allow-file-access-from-files \
  --virtual-time-budget=15000 --screenshot=portfolio-375.png \
  --window-size=500,2750 "file://$PWD/frame375.html"
```

```python
# (b) measure it instead of eyeballing it: CDP with an explicit viewport.
#     Reports documentElement.scrollWidth/clientWidth and every element whose
#     right edge exceeds the viewport. Script kept in the session scratchpad.
```

Result on this branch at 375px: `scrollWidth == clientWidth == 375`, **zero
overflowing elements**. The holdings table scrolls inside its own
`overflow-x-auto` container, which is the design's rule.

## 6. Live sanity calls (paced)

Against the real link — one call per endpoint, spaced, no sweeps. The source
allows 15 calls/min per tool, 30/min globally, and a breakdown costs 2.

```bash
H="x-alphadesk-admin-secret: some-local-secret"; B=http://127.0.0.1:8010
curl -s -o /dev/null -w "summary:%{http_code}\n"    -H "$H" "$B/portfolio/summary";                     sleep 5
curl -s -o /dev/null -w "holdings:%{http_code}\n"   -H "$H" "$B/portfolio/holdings?asset_type=MF";      sleep 5
curl -s -o /dev/null -w "allocation:%{http_code}\n" -H "$H" "$B/portfolio/allocation?asset_type=MF&by=sector"; sleep 3
curl -s -o /dev/null -w "history:%{http_code}\n"    -H "$H" "$B/portfolio/history?days=90"
```

All four answered `200` on the operator's live account. Structural findings
(no values recorded, deliberately):

- `link_health: linked`, `last_captured_at: null`, money fields all strings;
- the snapshot reports **four** cap bands including `Mega Cap` — one more than
  the design drew (SPECS §7) — and 13 sector buckets;
- `US_STOCK` and the out-of-enum `US_STOCK_WALLET` both carry `us_exposure`;
- `IND_STOCK` holdings returned `[]` (the account holds none), so the
  unverified-shape boundary did not fire. **It remains untested against a
  populated response** — see M1 §7; that boundary closes only with a capture
  from an account that holds Indian stocks.
- Running the backend outside single-tenant mode needs `IND_MONEY_MCP_URL` in
  the environment (it lives in `backend/.env`); without it every call fails as
  `source_unavailable`, which is the correct mapping but an easy self-inflicted
  confusion.

## 9. Manual interaction checks

**There is no frontend test runner in this repo** — no vitest/jest, no
Testing Library, no Playwright, and `npm run lint` does not run either (§2).
Adding one is a repo-wide decision with its own dependencies and config, so it
is not smuggled in under D1; these three behaviours are verified by hand
against the demo path (§4), and the procedure is written down so the next person
re-runs the same thing rather than inventing one.

### 9a. Sector drill-down cannot show stale data (the race guard)

The failure being tested: click chips faster than the source answers and the
slowest response wins, printing one asset type's sectors under another's
heading.

1. Run the demo path (§4) and open `/portfolio`.
2. DevTools → Network → throttle to **Slow 3G** (or `Fast 4G`; anything that
   makes the request visibly take a second). This is what makes the race
   reachable by hand at all — locally the fetch usually returns in ~20 ms.
3. Click the sector chips left to right as fast as you can: `Whole portfolio` →
   each asset-type chip in turn, ending on one you can identify by its buckets.
4. Assert, in order:
   - the card shows the pulsing **skeleton** (not the previous bars) from the
     moment each chip is pressed until its own response lands;
   - the Network panel shows the superseded `/portfolio/allocation` requests as
     **cancelled**;
   - when everything settles, the bars belong to the **last chip you clicked**
     and the heading reads `Within <that type> · fetched on demand`;
   - the card never shows the whole-portfolio breakdown under a `Within …`
     heading at any point.
5. Repeat with `Whole portfolio` clicked last: it must switch back instantly
   (it rides the snapshot, no request) and no late drill-down response may
   overwrite it afterwards.

Result on the fix commit: skeleton on every click, superseded requests
cancelled, final state matched the final click, no mismatched heading in ~20
rapid clicks.

### 9b. Refresh cooldown

1. Load `/portfolio`. **Refresh is already disabled** and counts down from
   `30s` — the initial load walks the same buckets a refresh would.
2. Click it repeatedly during the countdown: nothing fires (check Network).
3. At `0s` the label returns to `Refresh`; one click re-runs the load and the
   countdown restarts.
